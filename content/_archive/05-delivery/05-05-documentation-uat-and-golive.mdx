## 1. Purpose

Four named contract deliverables that are not components and not screens: the technical documentation,
the user guides, UAT support, and the cutover that makes the platform the system of record and turns
the legacy tool off.

The plan is explicit that these are **named D11 deliverables, not by-products**.

## 2. Scope

### In scope

- Technical documentation: architecture, data model, API reference, runbooks, adapter contracts
- User guides per internal role, plus in-app help content for candidates
- UAT support: defect intake, severity triage, turnaround, evidenced retest
- Go-live: cutover, system-of-record switch, legacy retirement, hypercare

### Explicitly out of scope

- These documents. `docs/` is engineering specification; the D11 technical documentation is generated
  from the shipped system (`01-04` §8) and covers what was actually built.
- Environments and the pipeline — `02-15`.
- The migration itself — `03-13`. Cutover **depends on** its reconciliation.
- Training delivery. Guides are produced; running training sessions is not scoped.

### Explicitly not built

- A customer-facing help centre or knowledge base.
- Video training material.
- Documentation for Release 2 capabilities that do not ship.

## 4. Dependencies

**Must exist first:** everything. These are cross-cutting and run to the end of the engagement.
Specifically: `02-15` (the environments UAT runs in), `03-13` (**reconciliation gates cutover**),
`02-13` (the adapter contract that must be documented well enough for a third party).

**Consumed by:** Apollo IT, Apollo operations, and any third party implementing a new market adapter.

**External:** `X22` — **named UAT participants with protected time**, agreed severity definitions and
turnaround, the go-live window and the parallel-run period.

## 6. State machines

### Go-live (`M1-I9`)

| From | Event | To | Rule |
|---|---|---|---|
| `pre-cutover` | migration reconciliation passes | `ready` | **`03-13` reconciliation is the gate; nothing else is** |
| `ready` | cutover executed in the agreed window | `cut_over` | A rollback point exists up to the agreed cutover commit |
| `cut_over` | parallel run completes | `system_of_record` | **The platform becomes system of record only after reconciliation passes** |
| `system_of_record` | parallel-run period closes | `legacy_retired` | **CPAL is retired only after the parallel run closes** |
| `legacy_retired` | hypercare period ends | `steady_state` | Hypercare coverage is defined and staffed before it starts |

### Defect (`M1-I8`)

`raised → triaged (severity agreed) → fixed → retested (evidenced) → closed`.
Severity definitions and turnaround windows are agreed **before testing starts, not negotiated during
it**.
