## 1. Purpose

Gets an offer signed. **Without it an accepted offer produces no signed document, and the permanent
chain has no joining event** — which means no placement, no trial, no day-90 record and no invoice.

**No provider is named** in either client document.

## 2. Scope

**In scope:** sending an offer for signature, receiving the signed document and signer evidence, status
updates without polling delay, per-envelope cost recording, and the provider interface.

**Explicitly out of scope:** offer generation and templates (`03-08`); offer delivery over WhatsApp
(`04-01`); the offer-to-contract mapping that follows signature (`03-08`); signing the **client**
contract, which happens outside the platform.

**Explicitly not built:** in-person or wet signature capture; witness or notarisation flows; signing
anything other than an offer.

## 4. Dependencies

**Must exist first:** `03-08` (the generated offer), `02-04` (the rendered and signed documents),
`02-02` (signer evidence is audit material), `02-10`.

**Consumed by:** `03-08` — signature moves the offer to `signed` and triggers the contract mapping,
which produces the joining event `03-09` consumes.

**External:** `X26` — **name the supplier; confirm the signature is valid for Indian employment offers;
confirm per-envelope pricing.**

## 5. Data model

`selection.offer_version.esign_envelope_id` and `signed_document_id` (`03-08`).

```ts
interface ESignProvider {
  send(i: { documentId: string; signerName: string; signerPhone: string; signerEmail?: string;
            callbackUrl: string }): Promise<{ envelopeId: string }>
  getStatus(envelopeId: string): Promise<{
    state: 'sent' | 'viewed' | 'signed' | 'declined' | 'expired'
    signedDocumentUrl?: string
    signerEvidence?: Record<string, unknown>    // retained for audit
    costUnits: number
  }>
}
```

## 6. State machines

Drives `selection.offer`: `sent → opened → signed`, or `declined` / `expired`. **Status updates arrive
by callback, not polling**, so the offer state is not stale on screen.

## 7. API surface

| Direction | Endpoint | Purpose |
|---|---|---|
| Outbound | in-process `esign.send()` | Called by `03-08` only |
| Inbound | `POST /hooks/esign/:provider` (via `edge-webhook`) | Signature status callback |

## 8. Events and jobs

`esign.send` on the `provider` class; `esign.reconcile` hourly as a backstop for a missed callback.
Events flow through `03-08` (`selection.offer.signed`).

## 9. Frontend

**N/A** — offer tracking is `03-08`, which distinguishes **viewed-but-unsigned from undelivered**.
