## 1. Purpose

Once someone accepts an offer, this module tracks them joining and then checks in on them at **day 0,
7, 30, 60 and 90**. The candidate is asked whether they are being paid on time, whether they have a
preceptor and whether their accommodation is sorted. The client is asked at day 30 and 60 how it is
going, and at day 90 **whether the person is still there** — that last answer is what lets Apollo
invoice.

The day-90 record is the single most consequential object in the platform. It must still make sense to
someone querying a charge a year later, so it is immutable, it snapshots the terms in force, and it
records whether the client acknowledged or the window simply expired.

## 2. Scope

### In scope

- Joining confirmation, opening the placement and starting the 90-day clock
- Placement list with trial stage and billing-trigger visibility for finance
- Drop-out capture with a reason, returning the position to the requisition
- **Privileging** for doctors — a hospital-granted permission separate from council registration
- Trial dashboard: which check-ins are done, due or missed
- Check-in configuration: which events, which questions, per candidate category **and per care setting**
- Candidate answers with escalation on a negative response
- Trial outcome, and the visible deemed-confirmation countdown
- Check-in scheduling on both sides, and question rendering across app, WhatsApp and voice
- The immutable day-90 record

### Explicitly out of scope

- Shift attendance and timesheets — `03-10`, even though both sit in M8.
- The client-facing check-in pages and the link mechanism — `02-14`.
- Invoicing against the day-90 record — `03-11`.
- Candidate messaging transport — `02-09` and `03-06`.

### Explicitly not built

- Paying anyone. Payroll runs outside the platform for this whole period — `03-17`.
- Salary changes, advances and holds — `03-16`.
- Joining paperwork and statutory forms — `03-15`.
- Leave, overtime and internal timesheet routing — `03-19`.
- Blocking a check-in based on location — `03-16`.
- **Running the privileging request process with the hospital.** Release 1 records the outcome
  (`OI-HS-16`).

## 4. Dependencies

**Must exist first:** `03-08` (**the accepted offer — without D20 there is no joining event at all**),
`02-14` (the link mechanism, built before this), `03-01` (the deemed-confirmation window), `03-06` and
`02-09` (candidate-side dispatch), `03-04` (category question sets), `02-03`.

**Consumed by:** `03-11` needs the day-90 record to raise a permanent invoice; `03-03` needs fill and
drop-out counts; `03-12` reports trial survival; `03-15` onboarding triggers from the placement.

**External:** `X29` — a named client recipient per placement, or the day-90 record is not defensible.

## 5. Data model

```sql
CREATE TABLE placement.placement (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    reference text NOT NULL UNIQUE,
    candidate_id uuid NOT NULL,
    requisition_id uuid NOT NULL,
    offer_id uuid NOT NULL,
    client_id uuid NOT NULL, location_id uuid NOT NULL, department_id uuid,
    contract_version_id uuid NOT NULL,        -- what M9 will read
    service_line text NOT NULL CHECK (service_line IN ('permanent','contractual')),
    joining_date date,
    state text NOT NULL DEFAULT 'offered' CHECK (state IN
      ('offered','joined','in_trial','trial_survived','trial_ended','dropped_out')),
    trial_day integer GENERATED ALWAYS AS (
      CASE WHEN joining_date IS NULL THEN NULL
           ELSE (CURRENT_DATE - joining_date) END) STORED,
    replacement_for_placement_id uuid REFERENCES placement.placement(id),  -- guarantee tracking
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);
CREATE INDEX ON placement.placement (state, joining_date);
CREATE INDEX ON placement.placement (client_id, state);

CREATE TABLE placement.privileging (          -- doctors only (M8-I10)
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    placement_id uuid NOT NULL REFERENCES placement.placement(id),
    location_id uuid NOT NULL,                -- held per placement AND per hospital
    state text NOT NULL DEFAULT 'requested'
      CHECK (state IN ('requested','granted','rejected','not_required')),
    granted_from date, rejected_reason text,
    recorded_by uuid, recorded_at timestamptz
);

CREATE TABLE placement.drop_out (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    placement_id uuid NOT NULL REFERENCES placement.placement(id),
    kind text NOT NULL CHECK (kind IN ('did_not_join','left_early')),
    reason_code text NOT NULL REFERENCES settings.list_entry(code),
    reason_text text,
    occurred_on date NOT NULL,
    recorded_by uuid NOT NULL, recorded_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE placement.check_in_config (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    day_offset integer NOT NULL,              -- 0, 7, 30, 60, 90 — configurable, not hardcoded
    audience text NOT NULL CHECK (audience IN ('candidate','client')),
    candidate_category text REFERENCES settings.list_entry(code),
    care_setting text REFERENCES settings.list_entry(code),   -- home care has no preceptor
    question_set jsonb NOT NULL,
    link_type_code text,                      -- client side binds to an A13 type
    escalate_after_hours integer,
    is_enabled boolean NOT NULL DEFAULT true,
    UNIQUE (day_offset, audience, candidate_category, care_setting)
);

CREATE TABLE placement.trial_event (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    placement_id uuid NOT NULL REFERENCES placement.placement(id),
    check_in_config_id uuid NOT NULL REFERENCES placement.check_in_config(id),
    day_offset integer NOT NULL,
    audience text NOT NULL,
    due_on date NOT NULL,
    state text NOT NULL DEFAULT 'scheduled' CHECK (state IN
      ('scheduled','due','answered','escalated','missed','cancelled')),
    client_link_id uuid,                      -- client side
    message_id uuid,                          -- candidate side
    fired_at timestamptz, answered_at timestamptz,
    UNIQUE (placement_id, day_offset, audience)
);
CREATE INDEX ON placement.trial_event (state, due_on);

CREATE TABLE placement.trial_response (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    trial_event_id uuid NOT NULL REFERENCES placement.trial_event(id),
    channel text NOT NULL CHECK (channel IN ('app','whatsapp','voice','client_link')),
    answers jsonb NOT NULL,   -- attendance, salary_on_time, preceptor_assigned, accommodation_ok
    needs_review boolean NOT NULL DEFAULT false,   -- voice/free text below threshold (OI-A-08)
    escalation_state text CHECK (escalation_state IN ('raised','in_progress','resolved')),
    escalation_note text,
    received_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE placement.retention_record (     -- IMMUTABLE. The permanent billing trigger.
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    placement_id uuid NOT NULL UNIQUE REFERENCES placement.placement(id),
    outcome text NOT NULL CHECK (outcome IN ('retained','not_retained')),
    basis text NOT NULL CHECK (basis IN ('acknowledged','deemed')),
    client_link_id uuid,                      -- null when deemed
    link_response_id uuid,
    recipient_id uuid,                        -- WHO acknowledged — what makes it defensible
    acknowledged_at timestamptz,
    deemed_at timestamptz,
    deemed_window_days integer,
    deemed_window_source text CHECK (deemed_window_source IN ('client','platform_default')),
    contract_version_id uuid NOT NULL,
    contract_terms_snapshot jsonb NOT NULL,   -- snapshotted, NOT resolved again later
    created_at timestamptz NOT NULL DEFAULT now()
);
REVOKE UPDATE, DELETE ON placement.retention_record FROM PUBLIC;
```

## 6. State machines

### `Placement` (`M8-I1`, `M8-I2`)

| From | Event | To | Rule |
|---|---|---|---|
| — | offer signed (`03-08`) | `offered` | |
| `offered` | joining confirmed | `joined` → `in_trial` | **A doctor cannot be confirmed as joined until privileging is granted.** Trial clock starts from the confirmed joining date |
| `offered` | did not join | `dropped_out` | Position returns to open in `03-03` |
| `in_trial` | left early | `trial_ended` | Reason required; **no retention record, therefore no permanent invoice** |
| `in_trial` | day-90 answer or deemed | `trial_survived` | Writes the immutable `RetentionRecord` |

A joining-date change **before day 0 reschedules the trial events**; fired events are left intact.

### `TrialEvent` (`M8-I11`)

`scheduled → due → answered`, or `escalated` (non-response escalates to outbound voice per the
configured timer), or `missed` — **and a missed check-in is distinguishable from a not-yet-due one**.

### `RetentionRecord` (`M8-I13`) — the one that matters

```
 day-90 client link issued ──▶ answered ──▶ RetentionRecord(basis='acknowledged', recipient_id, at)
                          └──▶ expired ──▶ window from ClientWindowConfig ?? platform default
                                       ──▶ RetentionRecord(basis='deemed', window + source recorded)
```

Immutable once created. Links to either the link response or the deemed event. Snapshots the contract
terms rather than referencing them, so a later amendment cannot change what the invoice was justified
by. Termination before day 90 produces **no record and no invoice**.

### `Privileging` (`M8-I10`)

`requested → granted | rejected`, or `not_required` for nurses and allied health. **Held per placement
and per hospital, not once per doctor.** Council registration in `03-04` does not satisfy it and does
not skip the step.

## 8. Events and jobs

**Events emitted:** `placement.placement.joined` · `placement.dropout.recorded` ·
`placement.trial_event.due` · `.answered` · `.missed` · `placement.trial_response.escalated` ·
`placement.retention.confirmed` · `.deemed` · `placement.privileging.granted`.

**Events subscribed:** `selection.offer.signed` → create the placement in `offered`;
`links.link.answered` (day 30/60/90) → write the trial response, and for day 90 **only**, the retention
record.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `placement.trial-events` | daily | Generates day 0/7/30/60/90 from the joining date; candidate side via `02-09`, **client side issues an A13 link of the correct type** |
| `placement.escalate-nonresponse` | hourly | Escalates to outbound voice on the configured timer |
| `placement.deem-retention` | hourly | Writes the deemed record once the window expires; **countdown visible before expiry, not only after** |

## 11. Open questions

| Ref | Question | Working assumption | Blocks |
|---|---|---|---|
| `OI-A-12` | The recipient identity model — the day-90 acknowledgement must be attributable to a named recipient | Resolved through `02-14`'s four-column recipient model. **Without it the billing trigger is not defensible**, so placements approaching day 90 without a designated recipient are flagged. | `M8-I13`, `M9-D8` |
| `OI-A-13` | **How long is the guarantee period, and does it run past day 90?** | Captured on the contract version and shown on the trial outcome. If longer than 90 days, a departure in month five means an already-raised invoice must be corrected, which **moves credit and debit notes out of Phase 7**. This changes scope, not just a number. **Estimate blocker.** | `M9-I12`, `M9-I1`, `M2-I8`, `M15-I5` |
| `OI-A-05` | Platform default deemed-confirmation window | 14 days, from `02-03`, labelled as a placeholder | `M8-I6`, `M8-I13` |
| `OI-HS-16` | **How is hospital privileging requested and returned?** Recording the grant is straightforward; whether the platform raises the request, tracks it and chases it is not stated | **Recording the outcome only.** Running the request process is a workflow with a client-facing surface and is several times the size. | `M8-I10` |
| `OI-A-08` | Voice and free-text trial responses below the confidence threshold | Routed to the same review queue as A14, never written back silently | `M8-I5` |
| `OI-HS-34` **[raised here]** | Does a home-healthcare trial question set exist, and who authors it? | A care-setting-specific set is built into the configuration; the **content** needs a clinical owner.
