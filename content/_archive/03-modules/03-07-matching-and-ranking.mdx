**Package** `@apollo/matching` · **Schema** `matching` · **Plan** D5, D18, A8 · **Effort** ~72.0pd · **Risk** High `MODEL` · **Build in** Phase 4 · **Release** Parts 1, 2, 3

## 1. Purpose

Given a vacancy, produce a ranked list of candidates, best first, with a plain explanation of why each
ranked where they did and which requirements they do not meet. Weights differ per candidate category
and per supply base, so there are **at least six sets**. Recruiters can search manually, can move
someone up or down, and every override is recorded. When a client or interviewer rejects someone with a
structured reason, that reason feeds back and affects later rankings.

The rejection taxonomy in `03-08` and the features this engine reads are **one design, not two**. If
the ranking model has no slot for outcome data, feeding rejections back later means rebuilding it. Both
schemas are agreed in a joint session before either module is built (Part A coupling 1).

## 2. Scope

### In scope

- Advanced candidate search on skill, location, experience and status, with saved searches
- Talent segments, **shared with the `03-06` cadence model rather than duplicated**
- The ranked set: score, rationale, met / partly met / unmet criteria, staleness
- Recruiter override with a mandatory reason, append-only
- Weight sets per category × base, versioned by effective date
- The ranking engine, producing rationale **as part of scoring, not reconstructed afterwards**
- Feature extraction from credentials, category attributes, availability, certifications and outcomes
- Weight-set selection, recorded on the ranked set
- Shift-level ranking against a shift demand line
- Outcome write-back from `03-08`
- Shortlist assembly and submission, which issues the client link

### Explicitly out of scope

- Interview, decision and offer — `03-08`. It **produces** the outcomes this module consumes.
- The client-facing shortlist page — `02-14`.
- The candidate record, credentials and attributes — `03-04`.
- Availability decay — `03-06`.

### Explicitly not built

- **Retraining the model automatically.** Release 1 applies a configured weight set; continuous
  learning is not in this contract.
- Showing candidates their own match score. Ranking is internal only.
- Sending a shortlist to a client without a recruiter pressing the button.
- Using the clinical and communication rating — nothing produces that value (`OI-A-07`).
- Ranking on a partial input set. It fails visibly instead.

## 4. Dependencies

**Must exist first — all three, and ranking cannot run on a partial set:** `03-03` (the requisition and
its category), `03-04` (credentials and category attributes), `03-06` (the freshness score). Plus
`02-03` (the rejection taxonomy), `02-07`, `02-14` (submission issues the link).

**Consumed by:** `03-08` takes the shortlist; everything after `03-08` depends on this indirectly.

**External:** none. The engine is deterministic scoring against configured weights, not a model API.

**Scheduling note:** the ranking-schema and rejection-taxonomy session with `03-08` happens **before
either starts**. The client also asks for a crude ranked list on three fields in front of recruiters in
week eight (gate G2b) — their overrides are the weighting specification.

## 5. Data model

```sql
CREATE TABLE matching.weight_set (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_category text NOT NULL REFERENCES settings.list_entry(code),
    base text NOT NULL CHECK (base IN ('base_a','base_b')),
    version integer NOT NULL,
    effective_from date NOT NULL,
    weights jsonb NOT NULL,   -- {credential:0.30, specialty_match:0.25, availability:0.20,
                              --  recency:0.10, outcomes:0.10, certification:0.05}
    eligibility_rules jsonb NOT NULL DEFAULT '{}'::jsonb,   -- filter vs weight (OI-HS-10)
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    UNIQUE (candidate_category, base, version)
);

CREATE TABLE matching.ranked_set (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    requisition_id uuid NOT NULL,
    shift_demand_line_id uuid,               -- non-null for shift ranking (M6-I10)
    weight_set_id uuid NOT NULL REFERENCES matching.weight_set(id),
    feature_version integer NOT NULL,        -- so a taxonomy change cannot silently alter old scores
    state text NOT NULL DEFAULT 'generating'
      CHECK (state IN ('generating','current','stale','failed')),
    stale_reason text,                       -- 'requisition_revised' | 'outcome_recorded'
    failure_reason text,                     -- missing category, credentials or availability
    generated_at timestamptz NOT NULL DEFAULT now(),
    generated_by uuid
);
CREATE INDEX ON matching.ranked_set (requisition_id, generated_at DESC);

CREATE TABLE matching.rank_entry (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    ranked_set_id uuid NOT NULL REFERENCES matching.ranked_set(id),
    candidate_id uuid NOT NULL,
    rank integer NOT NULL,
    score numeric(6,4) NOT NULL,
    rationale jsonb NOT NULL,   -- { met:[…], partially_met:[…], unmet:[…],
                                --   availability:{value, lastConfirmedAt, isStale},
                                --   absent:[{feature:'clinical_rating', reason:'no producing system'}] }
    state text NOT NULL DEFAULT 'ranked' CHECK (state IN
      ('ranked','shortlisted','sent_to_client','outcome_recorded')),
    UNIQUE (ranked_set_id, candidate_id)
);
CREATE INDEX ON matching.rank_entry (ranked_set_id, rank);

CREATE TABLE matching.recruiter_override (   -- append-only
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    ranked_set_id uuid NOT NULL REFERENCES matching.ranked_set(id),
    candidate_id uuid NOT NULL,
    from_rank integer NOT NULL, to_rank integer NOT NULL,
    reason_code text NOT NULL REFERENCES settings.list_entry(code),
    reason_text text,
    applied_by uuid NOT NULL, applied_at timestamptz NOT NULL DEFAULT now()
);
REVOKE UPDATE, DELETE ON matching.recruiter_override FROM PUBLIC;

CREATE TABLE matching.shortlist (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    requisition_id uuid NOT NULL,
    ranked_set_id uuid,
    state text NOT NULL DEFAULT 'draft' CHECK (state IN
      ('draft','submitted','awaiting_client','responded','superseded')),
    submitted_at timestamptz, submitted_by uuid,
    client_link_id uuid,                     -- links.client_link
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE matching.shortlist_entry (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    shortlist_id uuid NOT NULL REFERENCES matching.shortlist(id),
    candidate_id uuid NOT NULL,
    position integer NOT NULL,
    added_from text NOT NULL CHECK (added_from IN ('ranked_set','search')),
    override_applied boolean NOT NULL DEFAULT false,
    client_response text CHECK (client_response IN ('accepted','rejected','interview_requested')),
    client_reason_code text,
    responded_at timestamptz
);

CREATE TABLE matching.outcome_signal (       -- A8: what M7 writes back
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL,
    requisition_id uuid NOT NULL,
    signal_type text NOT NULL,   -- 'client_rejected' | 'interview_rejected' | 'selected'
                                 -- | 'offer_declined' | 'dropped_out'
    reason_code text,            -- from the shared taxonomy in 02-03
    stage text NOT NULL,
    occurred_at timestamptz NOT NULL,
    state text NOT NULL DEFAULT 'captured'
      CHECK (state IN ('captured','written_back','included')),
    written_back_at timestamptz
);
CREATE INDEX ON matching.outcome_signal (candidate_id, occurred_at DESC);

CREATE TABLE matching.saved_search (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    owner_id uuid NOT NULL, name text NOT NULL,
    definition jsonb NOT NULL, is_shared boolean NOT NULL DEFAULT false
);

CREATE TABLE matching.talent_segment (       -- shared with 03-06, defined once
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    name text NOT NULL,
    kind text NOT NULL CHECK (kind IN ('dynamic','static')),
    definition jsonb,                        -- dynamic: filters, refreshed on read
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE matching.talent_segment_member (   -- static segments only
    talent_segment_id uuid NOT NULL REFERENCES matching.talent_segment(id),
    candidate_id uuid NOT NULL,
    PRIMARY KEY (talent_segment_id, candidate_id)
);
```

## 6. State machines

### `RankedSet` (`M6-I3`, `M6-I6`)

| From | Event | To | Rule |
|---|---|---|---|
| — | generation requested | `generating` | |
| `generating` | scored | `current` | Rationale produced **as part of scoring** |
| `generating` | category, credentials or availability missing | `failed` | **Fails visibly rather than ranking on a partial input set** |
| `current` | requisition revised | `stale` | Marked and regenerable |
| `current` | outcome recorded for a ranked candidate | `stale` | |
| `current` | regenerated | `current` (new set) | **The prior set remains retrievable for audit** |

### `Shortlist` (`M6-I4`)

`draft → submitted → awaiting_client → responded`. Submission is an **explicit recruiter act**; nothing
is auto-submitted. Resubmission after a client response creates a **new** submission rather than
overwriting the first.

### `OutcomeSignal` (`M6-I9`)

`captured → written_back → included in the next ranking run`. Write-back is **asynchronous and does not
gate the offer stage**.

## 8. Events and jobs

**Events emitted:** `matching.ranked_set.generated` · `.failed` · `.stale` ·
`matching.override.applied` · `matching.shortlist.submitted` · `matching.outcome.written_back`.

**Events subscribed:** `demand.requisition.revised` → mark stale;
`selection.decision.recorded` and `links.link.answered` (shortlist type) → capture an outcome signal;
`placement.dropout.recorded` → capture an outcome signal.

**Jobs**

| Job | Trigger | Purpose |
|---|---|---|
| `matching.generate` | on demand | Extract features, select the weight set, score, produce rationale |
| `matching.write-back-outcome` | on outcome events | **Asynchronous; does not gate the offer stage** |
| `matching.bulk-shift-rank` | on demand | Ranks a period of shifts **without one run per shift** |

## 11. Open questions

| Ref | Question | Working assumption | Blocks |
|---|---|---|---|
| `OI-A-11` | **The relative weighting model across inputs, and its configurability, is not specified.** Three categories × two bases multiplies the weight sets, and the inputs themselves differ by category — the largest unspecified design in Release 1 | Built to **the more configurable of the two possibilities**: every input is a named, weighted, versioned feature per category × base.
