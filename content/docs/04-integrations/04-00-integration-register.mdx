## 2. Failure modes, and what happens

Every integration must degrade to something a person can work with. **No provider failure is allowed to
fail a candidate, lose a payload, or silently stop a business chain.**

| System | Failure | Platform behaviour |
|---|---|---|
| `04-01` WhatsApp | Provider down | Sends queue and retry; **the inbound webhook Lambda still records the payload** |
| `04-01` | Template not yet approved | **Send is refused, not attempted** — the template carries its approval state |
| `04-01` | 24-hour conversation window closed | Handled explicitly rather than the reply being lost |
| `04-02` SMS | DLT template rejected | Falls back to the next channel in the trigger's order |
| `04-03` Email | SES in sandbox | Only verified addresses receive mail — **looks like a product failure, is a configuration one** (`X03`) |
| `04-04` Voice | No answer | Retries per campaign policy within the call window and frequency caps |
| `04-04` | Extraction below threshold | **Review queue, never a silent confidence reset** |
| `04-05` STT | Transcription fails | Manual entry queue **with the audio retained and playable** |
| `04-05` | Voice note over the accepted duration | Manual entry, **not rejected** |
| `04-06` AI | Confidence below threshold | Manual entry queue; the rate is an operational load figure |
| `04-06` | Provider outage | Inbound records still written; classification retried; nothing discarded |
| `04-07` HRMS | Tenant unresolvable | Unmatched queue for manual selection |
| `04-08` Spreadsheet | Row fails mapping | **Named row-level error; valid rows still produce requisitions** |
| `04-09` Registry | No API for that council | **Document plus manual verification behind the same interface** |
| `04-09` | Aggregator outage | Manual fallback — **never fails the candidate**; surfaces as awaiting-registry pendency |
| `04-10` OCR | Extraction fails | Manual entry with the document retained |
| `04-11` E-sign | Provider down | Offer stays `sent`; signature status updates without polling delay when it returns |
| `04-12` Stores | Review rejection | **Calendar risk no team size removes** — a placeholder build goes through review early |
| `04-13` Finance | Not named | Generic API and file export; **a re-export does not duplicate in the target** |
| `04-14` Payroll | Person rejected by the engine | Reported with the engine's reason, correctable and resendable |
| `04-15` CPAL | Record will not map | Exception queue; corrected or rejected **with a reason, never lost** |

## 3. Cost instrumentation

Apollo has asked for consumption volumes. Part B asks for message and API volumes **per requisition**
across WhatsApp, email and transcription so running costs can be modelled. Every provider job records
its cost units attributed to a cause (`01-06` §4), and `03-06` projects volume before a cadence is
enabled.

The answer runs both ways: **Apollo needs a cost figure from Hiresense, and Hiresense needs Apollo's
expected base size and contact frequency to produce one** (`OI-HS-05`).

| Metered | Unit | Set by |
|---|---|---|
| WhatsApp | conversation | Cadence configuration, follow-up rate, link and offer delivery |
| SMS | segment | OTP volume, channel fallback |
| Voice | minute + inference | Base B size × cadence × no-answer retries |
| Speech-to-text | minute | Share of clients using voice notes |
| AI parsing | tokens | Inbound volume |
| OCR | page | Candidate intake rate × documents per category |
| Verification | check | Candidate intake rate × checks per category |
| E-signature | envelope | Offer volume |
| Payroll | associate per cycle | Base B working population |

## 4. Rules every integration obeys

1. **Behind an interface.** Half the suppliers are unnamed; each must be replaceable without a domain
   change. Adapters live in `02-13` for registries and in `integrations/*` for everything else.
2. **A stub adapter and a contract test ship with the integration**, so the consuming module is built
   and tested before the supplier is named.
3. **Never called inline.** Every provider call is a `provider`-class job (`02-10`), rate-limited to the
   provider's ceiling rather than discovered through throttling.
4. **In-region or not a candidate.** A provider that cannot process in `ap-south-1` fails `01-10`,
   whatever it costs.
5. **No real candidate data before the DPA is signed** (`X18`). Sandbox and synthetic data until then.
6. **Cost units recorded on every call**, attributed to a cause.
7. **Webhooks are Lambda-fronted, signature-verified and deduplicated** on provider message id
   (`01-09`).
8. **The failure path is tested**, not just the happy path — every integration has a test asserting the
   manual fallback rather than a crash.
