## 1. Purpose

The third-party engine that calculates pay. **We send inputs and take results back; we do not calculate
pay.** Hirecraft and PayBooks are the candidate engines; **neither is chosen.**

It sits behind an interface so it can be swapped later — the same pattern as the registry adapters in
`02-13`.

## 2. Scope

**In scope:** assembling and sending inputs for a locked cycle; receiving net pay, deductions and
payslip documents; reporting anyone the engine rejected, with its reason, correctable and resendable;
field mapping held as configuration; per-associate-per-cycle cost recording.

**Explicitly out of scope:** the pay run workflow and settings (`03-17`); statutory report generation
(`03-17`); onboarding completeness (`03-15`); payslip delivery (`02-09`).

**Explicitly not built:** **a payroll calculator**; statutory filing; a bank payment file (unless
confirmed as an addition); reversing a completed run inside the engine.

## 5. Data model

`payroll.input`, `payroll.output` and `payroll.blocked_associate` (`03-17`).

```ts
interface PayrollEngine {
  submitCycle(i: { cycleRef: string; periodStart: string; periodEnd: string
                   inputs: Array<Record<string, unknown>> })   // shaped by settings.field_mapping
    : Promise<{ engineRunId: string; accepted: number; rejected: Array<{ ref: string; reason: string }> }>
  getResults(engineRunId: string): Promise<{
    state: 'processing' | 'complete' | 'failed'
    results: Array<{ ref: string; gross: string; deductions: Record<string,string>
                     net: string; payslipUrl?: string }>
    costUnits: number
  }>
}
```

`field_mapping` is configuration (`03-17`, `M13-I2`), so **changing the engine changes a mapping, not
the platform.**

## 6. State machines

Drives `payroll.cycle`: `inputs_locked → sent → results_received`. A rejected input goes to
`payroll.input.rejected` **with the engine's reason, correctable and resendable** without re-locking the
whole cycle.

## 7. API surface

| Direction | Endpoint | Purpose |
|---|---|---|
| Outbound | in-process `payroll.submitCycle()` | Called by `03-17` only |
| Inbound | `POST /hooks/payroll/:provider` (via `edge-webhook`), or polled | Results, depending on what the engine offers |

## 8. Events and jobs

`payroll.send-to-engine` and `payroll.poll-results` on the `provider` class. Events flow through
`03-17`.
