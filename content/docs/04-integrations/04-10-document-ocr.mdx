## 1. Purpose

Reads registration certificates and identity documents so the verification team is not retyping them.
Returns **per-field confidence**, not a single document-level score, so a verifier can see which values
to check.

Sits behind the `02-13` adapter interface, so it can be replaced without a domain change. **No provider
is named.**

## 2. Scope

**In scope:** extraction from an uploaded document into typed fields with per-field confidence; failure
routing to manual entry with the document retained; per-page cost recording.

**Explicitly out of scope:** the document review screen (`03-04`, `M4-I14`); document storage and
scanning (`02-04`); CV parsing, which is `04-06`; deciding what a verification outcome means (`03-04`).

**Explicitly not built:** handwriting recognition beyond what the provider offers; document forgery
detection; auto-accepting an extraction without review.

**External:** provider **not named** (`OI-HS-07`).

## 5. Data model

`candidates.candidate_document.extracted` holds the machine output with per-field confidence;
`corrected` holds the verifier's values. **Both are retained**, which is what makes accuracy measurable.

```ts
interface OcrProvider {
  extract(i: { documentId: string; documentType: string }): Promise<{
    fields: Record<string, { value: string; confidence: number }>
    pages: number
    costUnits: number
  }>
}
```

## 6. State machines

Within `candidates.candidate_document`: `pending → accepted | rejected` by a verifier. Extraction itself
is stateless; a failure routes to manual entry **with the document retained**.

## 7. API surface

In-process `ocr.extract()`, triggered by `files.document.available`. No public endpoint.

## 8. Events and jobs

`ocr.extract` on the `provider` queue class, per-page cost recorded.

## 9. Frontend
