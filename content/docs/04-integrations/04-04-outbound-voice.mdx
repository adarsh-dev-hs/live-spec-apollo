## 1. Purpose

A5 calls candidates who have not responded on any other channel, asks whether they are still available,
and writes the answer back. **Apollo buys the calling service; Hiresense builds the integration and the
part that turns a spoken answer into structured data.**

Providers differ enormously in how conversations are handled, what the transcript looks like, and which
Indian languages are covered. **Apollo has not named one**, which is why this cannot be sized.

## 2. Scope

**In scope:** placing a call through the provider, returning the recording and transcript, retrying a
no-answer per campaign policy, storing recordings with residency and retention, per-minute cost
recording, and the provider interface itself.

**Explicitly out of scope:** campaign configuration and question sets (`03-06`); turning a transcript
into a structured answer (`03-06`'s `M5-I13`, though it is tightly coupled here); the voice service
itself, which Apollo buys.

**Explicitly not built:** inbound calls; a human call centre workflow; call recording review as a
quality process beyond the `03-06` review queue.

## 5. Data model

`engagement.voice_call` and `engagement.voice_campaign` (`03-06`). The provider contract:

```ts
interface VoiceProvider {
  placeCall(i: { to: string; scriptId: string; language: string;
                 callbackUrl: string }): Promise<{ providerCallId: string }>
  getResult(providerCallId: string): Promise<{
    state: 'completed' | 'no_answer' | 'busy' | 'failed'
    durationSeconds: number
    recordingUrl?: string
    transcript?: string
    structuredAnswers?: Record<string, unknown>   // some providers return this, some do not
    costUnits: number
  }>
}
```

`structuredAnswers` being optional is deliberate: a provider that returns structure removes most of
`M5-I13`, and one that returns only audio does not. **The difference is not knowable until the provider
is named.**

## 6. State machines

`queued → dialling → connected → completed`, or `no_answer → retry` within the campaign's call window
and frequency caps, or `failed`.

## 7. API surface

| Direction | Endpoint | Purpose |
|---|---|---|
| Outbound | in-process `voice.placeCall()` | Called only by `03-06` |
| Inbound | `POST /hooks/voice/:provider` (via `edge-webhook`) | Call completion callback with recording and transcript |
