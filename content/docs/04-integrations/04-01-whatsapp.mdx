## 1. Purpose

WhatsApp carries more of this platform's traffic than every other channel combined: inbound requisitions
as text and voice notes, the missing-field follow-up, cadence availability questions and their replies,
offer delivery, tokenised client links, trial check-ins and payslips.

**One registered number and one template set across all of it — not two.** The Business Solution
Provider must also approve every template before it can be used, which takes weeks and is outside
Apollo's control.

## 2. Scope

**In scope:** webhook receipt of text, voice notes, button and list replies; sender number resolution
handoff; template send with variable substitution; template approval state tracking; delivery and read
receipts; media download into `02-04`; the 24-hour conversation window; conversation counting for cost.

**Explicitly out of scope:** what a message means (`02-08` classifies, `03-02` and `03-06` interpret);
template authoring (`02-09`); voice **calls**, which are `04-04`.

**Explicitly not built:** two registered numbers; guided multi-step conversations (those live in the
app); WhatsApp as a support channel; interactive flows beyond templates with fixed buttons and lists.

## 5. Data model

No tables of its own. `inbound.inbound_record` carries `provider_message_id` for deduplication;
`messaging.template.provider_template_name` and `approval_state` carry the BSP state;
`messaging.message.cost_units` counts conversations.

```ts
// integrations/whatsapp/src/contract.ts
interface WhatsAppProvider {
  sendTemplate(i: { to: string; templateName: string; variables: Record<string,string>;
                    mediaDocumentId?: string }): Promise<{ providerMessageId: string; conversationId: string }>
  downloadMedia(mediaId: string): Promise<{ buffer: Buffer; contentType: string }>
  verifyWebhook(headers: Headers, body: Buffer): boolean
  submitTemplate(t: TemplateDefinition): Promise<{ providerTemplateName: string; state: ApprovalState }>
  getTemplateState(name: string): Promise<ApprovalState>
}
```

## 6. State machines

**Template approval:** `draft → submitted → approved | rejected`. An unapproved template **cannot be
sent** — enforced in the sender.

**Conversation window:** a session opens on an inbound message and closes 24 hours later. Outside it,
only an approved template may be sent; a reply arriving outside the window is **handled rather than
lost**.

**Message:** as `02-09`, with `delivered` and `read` from BSP receipts correcting an optimistic `sent`.

## 7. API surface

| Direction | Endpoint | Purpose |
|---|---|---|
| Inbound | `POST /hooks/whatsapp` (via `edge-webhook`) | Signature verified, deduped on message id, raw payload written, enqueued |
| Outbound | in-process `whatsapp.sendTemplate()` | Called only by `02-09`; nothing else touches the provider |
| Media | in-process `whatsapp.downloadMedia()` | Voice notes and documents into `02-04` |

## 8. Events and jobs

**Jobs:** `whatsapp.send` (`provider` class, rate-limited), `whatsapp.download-media`,
`whatsapp.sync-template-states` (hourly — approval lead time must be visible).

**Events:** emitted through `02-09` (`messaging.message.*`) and `02-08`
(`inbound.record.received`).
