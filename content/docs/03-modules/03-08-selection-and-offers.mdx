**Package** `@apollo/selection` · **Schema** `selection` · **Plan** D6, D20 · **Effort** ~63.5pd · **Risk** High `EXT` · **Build in** Phase 4–5

## 1. Purpose

Interviews, the decision, and the offer. Propose slots to a candidate and a client neither of whom has
a login, handle reschedules and cancellations, capture structured feedback, then accept, hold or reject
with a **mandatory reason from a configured taxonomy** — which is what feeds back into ranking. If
accepted, generate the offer from a template selected by state, role and skill, deliver it over
WhatsApp, track it to expiry, get it signed, and map it to the contract version whose terms `03-11`
will read at day 90.

Without offer management there is **no offer acceptance, no joining event**, and D7, A6, the A13
retention link and A7 invoicing all stall.

## 2. Scope

### In scope

- Interview slot proposal to both sides, confirmation, reschedule, cancellation with a reason
- Interview list showing what is awaiting feedback, so the pipeline does not stall silently
- Structured interview feedback that can feed the A8 write-back
- Accept / hold / reject with a mandatory structured reason and a full selection audit trail
- Offer templates by state, role and skill
- Offer generation, preview, delivery, tracking, expiry, reminders, decline with a reason
- Offer-to-contract mapping, capturing the placement fee `03-11` will read

### Explicitly out of scope

- The tokenised link mechanism and the client-facing shortlist page — `02-14`.
- Ranking and shortlist assembly — `03-07`.
- Offer delivery transport (`M7-I14`) — `04-01`; electronic signature (`M7-I15`) — `04-11`.
- Joining confirmation and the placement — `03-09`.

### Explicitly not built

- Any client login. The portal is Phase 6.
- AI video interviews. Later phase.
- Integration with interviewers' external calendars. Slots are proposed and confirmed **inside the
  platform**.
- Background checks at offer stage. Verification happens earlier, in `03-04`.
- A fifth link type for client-side interview feedback (`OI-HS-11`).

## 4. Dependencies

**Must exist first:** `03-07` (the shortlist), `03-01` (**the contract to map the offer to, and the
waiting periods**), `02-14` (client responses arrive by link), `02-09` (delivery), `02-03` (the

delivery.

## 5. Data model

```sql
CREATE TABLE selection.interview (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    requisition_id uuid NOT NULL,
    candidate_id uuid NOT NULL,
    shortlist_entry_id uuid,
    state text NOT NULL DEFAULT 'proposed' CHECK (state IN
      ('proposed','confirmed','held','feedback_recorded','rescheduled','cancelled','expired')),
    format text CHECK (format IN ('in_person','video','phone')),
    panel jsonb NOT NULL DEFAULT '[]'::jsonb,
    candidate_confirmed_at timestamptz,
    client_confirmed_at timestamptz,
    scheduled_start timestamptz, scheduled_end timestamptz,
    cancellation_reason_code text,
    reschedule_count integer NOT NULL DEFAULT 0,   -- repeated rescheduling is a risk signal
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE selection.interview_slot (      -- proposals, retained after confirmation
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    interview_id uuid NOT NULL REFERENCES selection.interview(id),
    starts_at timestamptz NOT NULL, ends_at timestamptz NOT NULL,
    proposed_at timestamptz NOT NULL DEFAULT now(),
    is_selected boolean NOT NULL DEFAULT false,
    superseded_by uuid REFERENCES selection.interview_slot(id)   -- reschedule keeps the original
);

CREATE TABLE selection.interview_feedback (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    interview_id uuid NOT NULL REFERENCES selection.interview(id),
    source text NOT NULL CHECK (source IN ('apollo','client_link')),
    interviewer_id uuid, client_link_id uuid,
    ratings jsonb NOT NULL,                  -- structured: dimensions differ by category
    comments text,
    submitted_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE selection.selection_decision (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    requisition_id uuid NOT NULL,
    candidate_id uuid NOT NULL,
    decision text NOT NULL CHECK (decision IN ('accepted','held','rejected')),
    reason_code text REFERENCES settings.list_entry(code),   -- MANDATORY on reject
    reason_text text,
    hold_expires_at timestamptz,             -- hold retains them on the shortlist with an expiry
    decided_by uuid NOT NULL, decided_at timestamptz NOT NULL DEFAULT now(),
    interview_feedback_id uuid REFERENCES selection.interview_feedback(id),
    CONSTRAINT reject_needs_reason CHECK (decision <> 'rejected' OR reason_code IS NOT NULL)
);
CREATE INDEX ON selection.selection_decision (candidate_id, requisition_id, decided_at);
REVOKE UPDATE, DELETE ON selection.selection_decision FROM PUBLIC;   -- append-only trail

CREATE TABLE selection.offer_template (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    state_code text NOT NULL,                -- Indian state; drives state-specific clauses
    role_code text NOT NULL, skill_code text,
    version integer NOT NULL, effective_from date NOT NULL,
    body text NOT NULL, variables jsonb NOT NULL,
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE selection.offer (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    requisition_id uuid NOT NULL, candidate_id uuid NOT NULL,
    selection_decision_id uuid NOT NULL REFERENCES selection.selection_decision(id),
    current_version integer NOT NULL DEFAULT 1,
    state text NOT NULL DEFAULT 'draft' CHECK (state IN
      ('draft','generated','sent','opened','signed','expired','declined','withdrawn')),
    expires_at timestamptz,
    declined_reason_code text,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE selection.offer_version (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    offer_id uuid NOT NULL REFERENCES selection.offer(id),
    version integer NOT NULL,
    offer_template_id uuid NOT NULL REFERENCES selection.offer_template(id),
    variables jsonb NOT NULL,                -- resolved from candidate, requisition and contract
    manual_adjustment jsonb,                 -- requires approval, audited
    approved_by uuid,
    document_id uuid,                        -- rendered offer in files.document
    signed_document_id uuid,
    esign_envelope_id text,
    sent_at timestamptz, opened_at timestamptz, signed_at timestamptz,
    UNIQUE (offer_id, version)
);

CREATE TABLE selection.offer_contract_mapping (
    offer_id uuid PRIMARY KEY REFERENCES selection.offer(id),
    contract_id uuid NOT NULL,
    contract_version_id uuid NOT NULL,       -- the version in force AT SIGNATURE
    placement_fee_pct numeric(5,2) NOT NULL, -- fixed here so M9 reads a settled figure at day 90
    ctc numeric(14,2), currency text NOT NULL DEFAULT 'INR',
    mapped_at timestamptz NOT NULL DEFAULT now()
);
```

## 6. State machines

### `Interview` (`M7-I1`, `M7-I2`)

| From | Event | To | Rule |
|---|---|---|---|
| — | slots proposed to both sides | `proposed` | Candidate via app/WhatsApp; client via a **tokenised link, no login** |
| `proposed` | **both** sides confirm | `confirmed` | Confirmation from both is required |
| `proposed` | nobody answers by the deadline | `expired` | **Returns to the recruiter for reissue; does not silently disappear** |
| `confirmed` | takes place | `held` | |
| `held` | feedback captured | `feedback_recorded` | |
| `proposed`/`confirmed` | rescheduled | `rescheduled` → `proposed` | **Original slot preserved in history**; both parties notified |
| any | cancelled | `cancelled` | **Reason from the taxonomy required**; candidate returns to the shortlist, not removed. Cancellation does **not** stop the requisition aging clock — only hold does. |

### `Offer` (`M7-I6`, `M7-I7`)

`draft → generated → sent → opened → signed`, or `expired` / `declined` / `withdrawn`.

- **Cannot be generated where the client has no active contract** or no mapping exists.
- Delivery is WhatsApp with email as an alternative; **viewed-but-unsigned is distinguishable from
  undelivered**.
- An expired offer is **reissued as a new version**, never reopened.
- A decline captures a reason feeding the A8 write-back.
- On signature the mapping fixes the contract version and placement fee, producing the joining event
  `03-09` consumes.

### `SelectionDecision` (`M7-I4`)

`pending → accepted | held | rejected`. Reject **requires** a structured reason — free text alone is
rejected. Accept moves the candidate to offer. Hold retains them on the shortlist with an expiry. Every
decision writes an append-only trail entry and triggers the asynchronous A8 write-back **without gating
the offer stage**.

## 8. Events and jobs

**Events emitted:** `selection.interview.proposed` · `.confirmed` · `.rescheduled` · `.cancelled` ·
`selection.feedback.recorded` · `selection.decision.recorded` · `selection.offer.generated` · `.sent` ·
`.opened` · `.signed` · `.expired` · `.declined` · `selection.offer.contract_mapped`.

**Events subscribed:** `links.link.answered` (shortlist type) → write the client response into the
selection record; `matching.shortlist.submitted` → open the selection stage.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `selection.expire-proposals` | hourly | Returns an unanswered slot proposal to the recruiter |
| `selection.offer-reminders` | daily | Chases sent-but-unsigned offers **to closure** |
| `selection.expire-offers` | hourly | Moves past-expiry offers to `expired` |
| `selection.map-contract` | on signature | Fixes contract version and placement fee |
| `selection.write-back-outcome` | on decision, decline and client rejection | Asynchronous into `03-07` |
