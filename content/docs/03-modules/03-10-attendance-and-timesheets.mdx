**Package** `@apollo/timesheets` · **Schema** `timesheets` · **Plan** D22 (thin slice) · **Effort** ~41.5pd · **Risk** High `SHARED` · **Build in** Phase 5

## 1. Purpose

The contractual invoice chain. Shift attendance arrives from app check-ins — **there is no other
route** — exceptions are resolved by a person, and the period is compiled into a timesheet priced
against the contract version in force. The client approves it through a tokenised link, or it is deemed
approved when the window expires, and `03-11` invoices against the **approved** timesheet rather than
raw attendance.

Attendance is recorded with a location stamp that is **not enforced** in Release 1. The field exists so
geo-fencing can be switched on in `03-16` without a data change.

## 2. Scope

### In scope

- Shift attendance: expected, checked in, checked out, no-show, with the location stamp recorded
- Exception resolution before a timesheet is compiled, including bulk resolution of a systemic cause
- Manual time correction with a mandatory reason, audited because it changes an invoice
- Timesheet compilation, pricing against the contract version, and reissue after correction
- Sending for approval, which issues the A13 timesheet link
- Timesheet tracking with the **visible deemed-approval countdown**
- The check-in receiver, including offline check-ins synced later
- The approved-timesheet export for the manual payroll process

### Explicitly out of scope

- The app check-in screen — `03-05`.
- The client approval page and link mechanism — `02-14`.
- Invoicing — `03-11`.
- Leave categorisation, overtime treatment and internal approval routing — `03-19`, Phase 7.
- Geo-fence enforcement and attendance upload from outside — `03-16`.
- Trial check-ins, which are a different thing entirely — `03-09`.

### Explicitly not built

- **Leave and overtime.** Explicitly out of the thin slice.
- Internal Apollo approval before the client sees the timesheet — `03-19`.
- Blocking a check-in on location. Recorded, not enforced.
- Silent amendment of an approved timesheet. A correction requires reissue.

## 5. Data model

```sql
CREATE TABLE timesheets.shift_attendance (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    shift_demand_line_id uuid NOT NULL,
    candidate_id uuid NOT NULL,
    shift_acceptance_id uuid,
    expected_start timestamptz NOT NULL, expected_end timestamptz NOT NULL,
    checked_in_at timestamptz, checked_out_at timestamptz,
    check_in_location point,                  -- RECORDED, not enforced (Part A CLOSED)
    check_out_location point,
    check_in_accuracy_m numeric(6,1),
    was_offline_sync boolean NOT NULL DEFAULT false,
    location_flag text CHECK (location_flag IN ('within_expected','outside_expected','unknown')),
    state text NOT NULL DEFAULT 'expected' CHECK (state IN
      ('expected','checked_in','checked_out','no_show','exception','resolved')),
    corrected_start timestamptz, corrected_end timestamptz,
    correction_reason text, corrected_by uuid, corrected_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX ON timesheets.shift_attendance (shift_demand_line_id, candidate_id);
CREATE INDEX ON timesheets.shift_attendance (state, expected_start);

CREATE TABLE timesheets.attendance_exception (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    shift_attendance_id uuid NOT NULL REFERENCES timesheets.shift_attendance(id),
    kind text NOT NULL CHECK (kind IN
      ('missing_check_in','missing_check_out','no_show','unmatched_check_in','location_outside')),
    state text NOT NULL DEFAULT 'open' CHECK (state IN ('open','resolved')),
    systemic_cause text,                      -- e.g. 'app_outage' — enables bulk resolution
    resolution text, resolution_reason text,
    resolved_by uuid, resolved_at timestamptz,
    raised_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE timesheets.timesheet (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    reference text NOT NULL UNIQUE,
    client_id uuid NOT NULL, location_id uuid NOT NULL,
    period_start date NOT NULL, period_end date NOT NULL,
    contract_version_id uuid NOT NULL,
    state text NOT NULL DEFAULT 'building' CHECK (state IN
      ('building','built','internally_approved','sent_for_approval',
       'approved','deemed_approved','queried','invoiced','void')),
    -- 'internally_approved' is added by 03-19 in Phase 7; unused before then
    has_unresolved_exceptions boolean NOT NULL DEFAULT false,
    total_hours numeric(8,2), total_value numeric(14,2), currency text NOT NULL DEFAULT 'INR',
    client_link_id uuid,
    sent_for_approval_at timestamptz,
    approval_window_days integer, approval_window_source text
      CHECK (approval_window_source IN ('client','platform_default')),
    approved_at timestamptz, approved_by_recipient_id uuid,
    deemed_at timestamptz,
    reissued_from uuid REFERENCES timesheets.timesheet(id),
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    UNIQUE (client_id, location_id, period_start, period_end, reference)
);
CREATE INDEX ON timesheets.timesheet (state, sent_for_approval_at);

CREATE TABLE timesheets.timesheet_line (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    timesheet_id uuid NOT NULL REFERENCES timesheets.timesheet(id),
    shift_attendance_id uuid NOT NULL,
    candidate_id uuid NOT NULL,
    shift_date date NOT NULL,
    hours numeric(6,2) NOT NULL,
    rate_card_line_id uuid, rate numeric(14,2) NOT NULL,
    value numeric(14,2) NOT NULL,
    has_exception boolean NOT NULL DEFAULT false,
    client_query_reason text                  -- a queried line routes back without blocking the rest
);

CREATE TABLE timesheets.timesheet_export (    -- the manual-payroll handoff (M8-I17, OI-A-15)
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid, period_start date NOT NULL, period_end date NOT NULL,
    document_id uuid NOT NULL,
    row_count integer NOT NULL,
    exported_by uuid NOT NULL, exported_at timestamptz NOT NULL DEFAULT now(),
    is_repeat boolean NOT NULL DEFAULT false  -- the same period cannot be silently exported twice
);
```

## 6. State machines

### `ShiftAttendance` (`M8-I7`, `M8-I14`)

| From | Event | To | Rule |
|---|---|---|---|
| — | shift accepted | `expected` | |
| `expected` | check-in received | `checked_in` | Location **stamped, not checked**; offline sync keeps the **original timestamp** |
| `checked_in` | check-out received | `checked_out` | Ready for the timesheet |
| `expected` | shift passes with no check-in | `no_show` | **Distinguishable from a missing check-in** |
| `checked_in` | shift passes with no check-out | `exception` | **Does not silently become a full shift or a zero shift** |
| — | check-in with no matching shift | `exception` | Raised, **never discarded** |
| `exception` | resolved with a reason | `resolved` | Attributed and audited — it changes billable hours |

### `Timesheet` (`M8-I8`, `M8-I15`, `M8-I16`)

| From | Event | To | Rule |
|---|---|---|---|
| — | period opens | `building` | Lines accumulate from resolved attendance |
| `building` | compiled | `built` | Priced against the contract version in force. **Flagged if exceptions remain unresolved** |
| `built` | sent | `sent_for_approval` | Issues the A13 timesheet link; the countdown starts **when the link is sent** |
| `sent_for_approval` | client approves | `approved` | Recipient recorded |
| `sent_for_approval` | window expires | `deemed_approved` | Per-client window, platform default fallback. **As valid an invoice input as an explicit approval** |
| `sent_for_approval` | client queries a line | `queried` | **Routes back to Ops without approving the whole timesheet** |
| `approved`/`deemed_approved` | invoiced by `03-11` | `invoiced` | One invoice per timesheet period, ever |
| `approved`/`invoiced` | correction needed | `void` + new timesheet | **Reissued, not silently amended** |

`03-19` inserts `internally_approved` between `built` and `sent_for_approval` in Phase 7. The client
window still starts only when the link is actually sent.

## 8. Events and jobs

**Events emitted:** `timesheets.attendance.checked_in` · `.checked_out` · `.exception_raised` ·
`.corrected` · `timesheets.timesheet.built` · `.sent_for_approval` · `.approved` · `.deemed_approved` ·
`.queried` · `.invoiced` · `timesheets.export.taken`.

**Events subscribed:** `candidates.shift.accepted` → create the `expected` row;
`links.link.answered` (timesheet type) → approve or query; `links.link.deemed` → deemed approval.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `timesheets.detect-no-shows` | hourly | Raises exceptions after a shift window closes |
| `timesheets.build` | daily / on demand | Compiles the period, resolves rates via `03-01`, prices lines |
| `timesheets.deem-approval` | hourly | Marks deemed approved when the window expires; **countdown visible before expiry** |
| `timesheets.export` | on demand or scheduled | The manual-payroll handoff |
