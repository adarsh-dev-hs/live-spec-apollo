**Package** `@apollo/billing` (extension) · **Schema** `billing` · **Plan** D25 (full) · **Effort** ~24.5pd · **Risk** Low `XMOD` · **Build in** Phase 7

## 1. Purpose

The money coming back in. `03-11` ends at *invoice raised, receivable open*; this module records
payments received, matches them against invoices including **part-payments and TDS**, shows what is
overdue and how overdue, chases automatically, and issues credit and debit notes to correct an invoice
already raised.

Together with `03-19` these turn the platform from one that raises invoices into one that tracks
whether Apollo actually got paid.

## 2. Scope

### In scope

- Payments received, matched across several invoices, with part-payments and unmatched payments queued
- TDS recorded separately so gross and net are both visible
- Overdue report with ageing **calculated from the contract payment terms**, not a flat rule
- Chase history, so a client is not chased twice
- Automatic dunning on a schedule, stopping the moment payment arrives
- Credit and debit notes, approved before issue and exported alongside invoices

### Explicitly out of scope

- Invoicing and receivables — `03-11`, which this extends.
- The finance system — `04-13`. This module still does not become the book of record.
- The messaging layer — `02-09`.
- The approval engine — `03-16`.

### Explicitly not built

- **Being the accounting system of record.** The finance system stays the book of record; this tracks
  against it.
- Bank statement import or automatic reconciliation. Payments are recorded, then matched by a person.
- Legal escalation beyond a formal notice.

## 5. Data model

```sql
CREATE TABLE billing.payment (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL,
    amount numeric(14,2) NOT NULL,
    currency text NOT NULL DEFAULT 'INR',
    received_on date NOT NULL,
    method text, reference text,
    tds_amount numeric(14,2) NOT NULL DEFAULT 0,   -- recorded SEPARATELY: gross and net both visible
    unmatched_amount numeric(14,2) NOT NULL,        -- sits in a queue, never forced onto the nearest invoice
    state text NOT NULL DEFAULT 'received'
      CHECK (state IN ('received','part_matched','matched')),
    recorded_by uuid NOT NULL, recorded_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE billing.payment_allocation (       -- many-to-many: one payment across several invoices,
    id uuid PRIMARY KEY DEFAULT uuidv7(),        -- one invoice taking several payments
    payment_id uuid NOT NULL REFERENCES billing.payment(id),
    invoice_id uuid NOT NULL REFERENCES billing.invoice(id),
    amount numeric(14,2) NOT NULL CHECK (amount > 0),
    allocated_by uuid NOT NULL, allocated_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON billing.payment_allocation (invoice_id);

CREATE TABLE billing.credit_note (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    reference text NOT NULL UNIQUE,
    note_type text NOT NULL CHECK (note_type IN ('credit','debit')),
    invoice_id uuid NOT NULL REFERENCES billing.invoice(id),
    amount numeric(14,2) NOT NULL,
    reason_code text NOT NULL REFERENCES settings.list_entry(code),
                                                 -- includes 'replacement_within_guarantee' (OI-A-13)
    reason_text text,
    approval_request_id uuid,                    -- issuing REQUIRES approval: it changes revenue
    state text NOT NULL DEFAULT 'draft'
      CHECK (state IN ('draft','awaiting_approval','issued','exported','cancelled')),
    document_id uuid,
    issued_at timestamptz, exported_at timestamptz,
    created_by uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE billing.dunning_schedule (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid,                              -- null = platform default
    steps jsonb NOT NULL,   -- [{daysOverdue, action:'reminder'|'owner'|'formal_notice', templateCode}]
    is_enabled boolean NOT NULL DEFAULT true
);

CREATE TABLE billing.dunning_event (             -- so a client is not chased twice
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    invoice_id uuid NOT NULL REFERENCES billing.invoice(id),
    step_index integer NOT NULL,
    action text NOT NULL,
    message_id uuid,                             -- messaging.message
    sent_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (invoice_id, step_index)
);
```

## 6. State machines

### `Receivable`, extended

`open → part_settled → settled`, or `written_off`. Also reduced by an issued credit note.

### `Payment` (`M15-I3`)

| From | Event | To | Rule |
|---|---|---|---|
| — | recorded | `received` | `unmatched_amount` = full amount |
| `received` | allocated to one or more invoices | `part_matched` | **A payment can be matched across several invoices, and an invoice can take several payments** |
| `part_matched` | fully allocated | `matched` | |
| any | remainder | stays unmatched | **Sits in a queue rather than being forced onto the nearest invoice** |

### `CreditNote` (`M15-I5`)

`draft → awaiting_approval → issued → exported`. **Issuing requires approval, because it changes
revenue.** A credit note reduces the receivable and is linked to the invoice it corrects.

### Dunning (`M15-I7`)

Steps fire on days-overdue thresholds: reminder → account owner → formal notice. **Stops as soon as
payment arrives.** Every chase is logged.

## 8. Events and jobs

**Events emitted:** `billing.payment.recorded` · `.allocated` · `billing.receivable.settled` ·
`billing.credit_note.issued` · `billing.dunning.sent`.

**Events subscribed:** `billing.invoice.raised` → schedule dunning from the contract payment terms.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `billing.dunning` | daily | Fires the next due step; **stops the moment the invoice is paid** |
| `billing.age-receivables` | daily | Recomputes ageing bands from contract terms |
| `billing.export-notes` | on issue | Notes exported to the finance system **alongside invoices** |
