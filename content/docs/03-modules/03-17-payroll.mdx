## 1. Purpose

Paying the shift workers. This connects the platform to a **third-party payroll engine — we do not
build a payroll calculator**. It assembles the inputs the engine needs, configures the pay cycle, takes
the results back, produces the PF and ESIC reports and challans, and delivers payslips in the app and
over WhatsApp.

Until this exists payroll is done by hand, which puts **a hard ceiling on how many shift workers Apollo
can take on** (`OI-A-16`). It is the last milestone and sits behind three others, so it is the item most
exposed to everything upstream.

## 2. Scope

### In scope

- Pay run: open a cycle, lock inputs, send, receive results, issue payslips, close
- Payroll settings: cycle frequency, cut-off dates, field mapping to the engine, deduction rates
- Statutory reports: PF and ESIC reports and challans for a period
- Payslips in the app and over WhatsApp
- The engine integration boundary: assemble inputs, take back outputs, report exceptions

### Explicitly out of scope

- The payroll engine itself — `04-14`. Hirecraft and PayBooks are the candidates; **not chosen**.
- Approved timesheets, salary revisions, advances and holds — `03-10`, `03-19`, `03-16` produce them.
- Onboarding completeness — `03-15` gates the run.
- The app payslip screen's shell — `03-05`; this module owns the screen.

### Explicitly not built

- **Calculating pay.** A third-party engine does that.
- **Submitting statutory filings.** Reports and challans are produced; someone else files them.
- Payroll for permanent placements. Those people are the client's employees.
- Reversing or re-running a closed cycle without an audited override.

## 5. Data model

```sql
CREATE TABLE payroll.settings (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    cycle_frequency text NOT NULL CHECK (cycle_frequency IN ('monthly','fortnightly','weekly')),
    cut_off_day integer NOT NULL,
    pay_day integer NOT NULL,
    engine_code text,                          -- 'hirecraft' | 'paybooks' | … — not chosen
    field_mapping jsonb NOT NULL,              -- platform field → engine field; changes without a release
    deduction_rates jsonb NOT NULL,            -- statutory rates as CONFIGURATION, updatable without a release
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);

CREATE TABLE payroll.cycle (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    period_start date NOT NULL, period_end date NOT NULL,
    state text NOT NULL DEFAULT 'open' CHECK (state IN
      ('open','inputs_locked','sent','results_received','payslips_issued','closed','failed')),
    locked_at timestamptz, locked_by uuid,
    sent_at timestamptz, results_received_at timestamptz, closed_at timestamptz,
    reopened_reason text, reopened_by uuid,    -- an audited override
    associate_count integer, blocked_count integer,
    UNIQUE (period_start, period_end)
);

CREATE TABLE payroll.input (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    cycle_id uuid NOT NULL REFERENCES payroll.cycle(id),
    associate_profile_id uuid NOT NULL,
    -- FROZEN at lock, so what was sent matches what was recorded
    hours numeric(8,2), rate numeric(14,2),
    timesheet_ids uuid[] NOT NULL DEFAULT '{}',
    salary_revision_id uuid, advance_recovery numeric(14,2) NOT NULL DEFAULT 0,
    is_held boolean NOT NULL DEFAULT false,
    adjustments jsonb NOT NULL DEFAULT '[]'::jsonb,
    state text NOT NULL DEFAULT 'draft'
      CHECK (state IN ('draft','validated','sent','rejected','accepted')),
    rejection_reason text,                     -- from the engine, correctable and resendable
    UNIQUE (cycle_id, associate_profile_id)
);

CREATE TABLE payroll.output (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    cycle_id uuid NOT NULL REFERENCES payroll.cycle(id),
    payroll_input_id uuid NOT NULL UNIQUE REFERENCES payroll.input(id),
    gross numeric(14,2), deductions jsonb, net numeric(14,2),
    payslip_document_id uuid,
    received_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE payroll.blocked_associate (       -- who cannot be paid, and why (M11-I5)
    cycle_id uuid NOT NULL REFERENCES payroll.cycle(id),
    associate_profile_id uuid NOT NULL,
    reason text NOT NULL,                      -- incomplete onboarding, missing document, hold
    override_request_id uuid,                  -- an override requires approval and is audited
    PRIMARY KEY (cycle_id, associate_profile_id)
);

CREATE TABLE payroll.statutory_report (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    cycle_id uuid NOT NULL REFERENCES payroll.cycle(id),
    report_type text NOT NULL CHECK (report_type IN ('pf_ecr','esic_return','pf_challan','esic_challan')),
    document_id uuid NOT NULL,
    reconciles_to_cycle boolean NOT NULL,      -- must reconcile to the run it came from
    generated_at timestamptz NOT NULL DEFAULT now(), generated_by uuid NOT NULL
);
```

## 6. State machines

### `PayrollCycle` (`M13-I1`)

| From | Event | To | Rule |
|---|---|---|---|
| — | period opens | `open` | Inputs accumulate |
| `open` | lock | `inputs_locked` | **Cannot lock while associates are blocked on incomplete onboarding.** Inputs are frozen so what is sent matches what is recorded |
| `inputs_locked` | send to engine | `sent` | Through `04-14` |
| `sent` | results returned | `results_received` | **Every person sent is accounted for, or reported as an exception** |
| `results_received` | payslips issued | `payslips_issued` | App and WhatsApp, through `02-09` |
| `payslips_issued` | closed | `closed` | |
| `closed` | reopened | `open` | **Requires an audited override** |

### `PayrollInput`

`draft → validated → sent → accepted`, or `rejected` by the engine **with its reason, correctable and
resendable**.

## 8. Events and jobs

**Events emitted:** `payroll.cycle.locked` · `.sent` · `.results_received` · `.closed` · `.reopened` ·
`payroll.input.rejected` · `payroll.payslip.issued` · `payroll.statutory_report.generated`.

**Events subscribed:** `timesheets.timesheet.approved` and `.deemed_approved` → assemble inputs;
`workforce.request.applied` → apply approved revisions, advances and holds;
`onboarding.associate.blocked` → add to the blocked list.

**Jobs**

| Job | Trigger | Purpose |
|---|---|---|
| `payroll.assemble-inputs` | daily during an open cycle | From approved timesheets, revisions, advances and holds |
| `payroll.evaluate-blocked` | before lock | Recomputes who cannot be paid |
| `payroll.send-to-engine` | on send, `provider` class | Through `04-14` |
| `payroll.issue-payslips` | on results | App and WhatsApp, **reusing `02-09`, not a separate sender** |
