**Package** `@apollo/billing` · **Schema** `billing` · **Plan** D8, A7, D25 (thin slice) · **Effort** ~45.0pd · **Risk** High `XMOD` · **Build in** Phase 5–6

## 1. Purpose

Two invoice paths and the evidence behind each. A **permanent placement** invoices once the client
confirms at day 90 that the person is still there — not at placement. A **contractual engagement**,
including a locum doctor paid per session, invoices from a client-approved timesheet. The trigger
follows the **service line, not the candidate category**.

Both must keep the evidence that caused them, because Apollo may be asked months later to justify a
charge. The chain ends at *invoice raised, receivable open*; collections are Phase 7.

## 2. Scope

### In scope

- Invoice list across both types, each linked to the evidence that allowed it
- Billing evidence: who confirmed, when, against which contract terms, acknowledged or deemed
- Receivables — money owed, with ageing displayed
- Permanent invoice generation from the day-90 record, at the terms in force at the trigger
- The immutable day-90 record store with snapshotted terms
- Contract-terms resolution at the trigger event, recorded on the invoice
- Shift invoice generation from an approved (or deemed-approved) timesheet
- Duplicate prevention on both paths

### Explicitly out of scope

- The invoice API and file export for a finance system — `04-13` (`M9-I16`).
- Reporting — `03-12`. Two workstreams sharing nothing but the event data.
- The day-90 record's creation — `03-09` writes it; this module reads it.
- Timesheet approval — `03-10` and `02-14`.

### Explicitly not built

- **Payment receipt, reconciliation including part-payments and TDS, ageing action, reminders,
  dunning, and credit or debit notes.** All Phase 7 (`03-20`) — unless `OI-A-13` moves credit notes
  forward.
- The finance system itself. Nobody has said which one it is (`OI-A-14`).
- Demand forecasting.
- Any client-facing invoice view before Phase 6.

## 5. Data model

```sql
CREATE TABLE billing.billing_trigger (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    trigger_type text NOT NULL CHECK (trigger_type IN ('retention_day_90','approved_timesheet')),
    placement_id uuid,                         -- permanent
    retention_record_id uuid,                  -- placement.retention_record
    timesheet_id uuid,                         -- contractual
    client_id uuid NOT NULL,
    contract_version_id uuid NOT NULL,
    terms_snapshot jsonb NOT NULL,             -- what was read, not a reference to be re-resolved
    basis text NOT NULL CHECK (basis IN ('acknowledged','deemed')),
    recipient_id uuid,                         -- who acknowledged (null when deemed)
    evidence_link_id uuid,                     -- links.client_link
    state text NOT NULL DEFAULT 'pending'
      CHECK (state IN ('pending','confirmed','consumed','void')),
    occurred_at timestamptz NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT one_source CHECK (num_nonnulls(retention_record_id, timesheet_id) = 1)
);
-- a placement can produce exactly one permanent trigger, ever
CREATE UNIQUE INDEX ON billing.billing_trigger (placement_id)
  WHERE trigger_type = 'retention_day_90' AND state <> 'void';
CREATE UNIQUE INDEX ON billing.billing_trigger (timesheet_id)
  WHERE trigger_type = 'approved_timesheet' AND state <> 'void';
REVOKE UPDATE (terms_snapshot, basis, recipient_id, occurred_at)
  ON billing.billing_trigger FROM PUBLIC;

CREATE TABLE billing.invoice (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    reference text NOT NULL UNIQUE,            -- INV-2026-000118
    invoice_type text NOT NULL CHECK (invoice_type IN ('permanent_placement','shift')),
    billing_trigger_id uuid NOT NULL UNIQUE REFERENCES billing.billing_trigger(id),
    client_id uuid NOT NULL,
    contract_version_id uuid NOT NULL,         -- recorded for audit (M9-I1)
    period_start date, period_end date,        -- shift invoices
    subtotal numeric(14,2) NOT NULL,
    tax numeric(14,2) NOT NULL DEFAULT 0,
    total numeric(14,2) NOT NULL,
    currency text NOT NULL DEFAULT 'INR',
    state text NOT NULL DEFAULT 'draft'
      CHECK (state IN ('draft','raised','exported','cancelled')),
    document_id uuid,                          -- rendered invoice
    raised_at timestamptz, exported_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE billing.invoice_line (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    invoice_id uuid NOT NULL REFERENCES billing.invoice(id),
    description text NOT NULL,
    candidate_id uuid, placement_id uuid, timesheet_line_id uuid,
    quantity numeric(10,2) NOT NULL DEFAULT 1,
    unit_rate numeric(14,2) NOT NULL,
    amount numeric(14,2) NOT NULL,
    basis jsonb NOT NULL                       -- CTC and fee %, or hours and shift rate
);

CREATE TABLE billing.receivable (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    invoice_id uuid NOT NULL UNIQUE REFERENCES billing.invoice(id),
    client_id uuid NOT NULL,
    amount_due numeric(14,2) NOT NULL,
    amount_settled numeric(14,2) NOT NULL DEFAULT 0,   -- moved by 03-20 in Phase 7
    due_date date,                                     -- from contract payment terms
    state text NOT NULL DEFAULT 'open'
      CHECK (state IN ('open','part_settled','settled','written_off')),
    opened_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON billing.receivable (client_id, state, due_date);
```

## 6. State machines

### `BillingTrigger` (`M9-I12`, `M9-I15`)

| From | Event | To | Rule |
|---|---|---|---|
| — | day-90 record written, or timesheet approved/deemed | `pending` | Terms **snapshotted at creation** |
| `pending` | validated — active contract, no prior invoice | `confirmed` | |
| `pending` | no active contract at trigger time | `void` | **Raises an exception rather than invoicing on defaults** |
| `confirmed` | invoice raised | `consumed` | **A duplicate trigger cannot produce a second invoice for the same placement** |

### `Invoice`

`draft → raised → exported`. `cancelled` exists only for a genuine error and requires the same approval
a credit note will require in Phase 7. Raising opens a `Receivable`.

### Which trigger applies

```
service_line = 'permanent'    ──▶ RetentionRecord at day 90 (acknowledged or deemed)
service_line = 'contractual'  ──▶ Timesheet in state approved or deemed_approved
```

A **locum doctor is contractual** and invoices per session against an approved timesheet, even though
the candidate category is doctor. The trigger follows the service line (`M9-I1`, letter item 9).

## 8. Events and jobs

**Events emitted:** `billing.trigger.created` · `.voided` · `billing.invoice.raised` · `.cancelled` ·
`billing.receivable.opened`.

**Events subscribed:** `placement.retention.confirmed` and `.deemed` → create a permanent trigger;
`timesheets.timesheet.approved` and `.deemed_approved` → create a shift trigger;
`clients.contract.terminated` → flag affected pending triggers.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `billing.trigger-sweep` | daily | Validates pending triggers and raises invoices |
| `billing.render-invoice` | on raise | Produces the document into `02-04` |
| `billing.export` | on raise | Hands to `04-13`; **a re-export does not duplicate in the target** |
