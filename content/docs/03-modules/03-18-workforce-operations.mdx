## 1. Purpose

The day-to-day changes that happen once people are working: salary revisions for one person or in
bulk, salary advances, and putting a salary on hold or releasing it. **Each needs two people — one to
request and one to approve — so nobody can change their own pay.**

It also covers uploading attendance from outside and pairing it against what the app recorded, and it
is where **geo-fencing on shift check-in finally gets switched on and enforced**.

> The approval engine here is reused by M15, so **build it first of the two.**

## 5. Data model

### 5.1 Salary revision

```sql
CREATE TABLE place.salary_revision (
  id                uuid PRIMARY KEY,
  associate_id      uuid NOT NULL,
  approval_request_id uuid NOT NULL,          -- platform.approval_request — ALWAYS
  batch_id          uuid,                     -- bulk: one request PER PERSON
  previous_amount   numeric(14,2) NOT NULL,
  new_amount        numeric(14,2) NOT NULL,
  change_percent    numeric(6,3) NOT NULL,
  effective_from    date NOT NULL,
  reason_code       text NOT NULL,
  status            revision_status_enum NOT NULL,   -- 'pending'|'approved'|'rejected'|'applied'
  applied_at        timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);
CREATE INDEX idx_revision__associate ON place.salary_revision (associate_id, effective_from DESC);
```

### 5.2 Advances and holds

```sql
CREATE TABLE place.salary_advance (
  id                uuid PRIMARY KEY,
  associate_id      uuid NOT NULL,
  approval_request_id uuid NOT NULL,
  amount            numeric(14,2) NOT NULL,
  reason            text NOT NULL,
  -- HOW it will be recovered, not just that it was paid
  recovery_method   recovery_method_enum NOT NULL,   -- 'single_deduction'|'instalments'
  recovery_instalments integer,
  recovery_start_cycle date NOT NULL,
  amount_recovered  numeric(14,2) NOT NULL DEFAULT 0,
  status            advance_status_enum NOT NULL,     -- 'pending'|'approved'|'disbursed'|
                                                      -- 'recovering'|'recovered'|'written_off'
  disbursed_at      timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE place.salary_hold (
  id                uuid PRIMARY KEY,
  associate_id      uuid NOT NULL,
  approval_request_id uuid NOT NULL,
  reason_code       text NOT NULL,
  hold_from_cycle   date NOT NULL,
  status            hold_status_enum NOT NULL,        -- 'pending'|'approved'|'held'|'released'
  released_at       timestamptz,
  release_approval_request_id uuid,                   -- releasing ALSO needs approval
  release_from_cycle date,
  created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);
```

### 5.3 Attendance upload

```sql
CREATE TABLE place.attendance_upload (
  id             uuid PRIMARY KEY,
  document_id    uuid NOT NULL,
  client_id      uuid, location_id uuid,
  period_start date NOT NULL, period_end date NOT NULL,
  status         upload_status_enum NOT NULL,
  row_count integer NOT NULL DEFAULT 0,
  matched_count integer NOT NULL DEFAULT 0,
  mismatch_count integer NOT NULL DEFAULT 0,
  error_count integer NOT NULL DEFAULT 0,
  uploaded_at timestamptz NOT NULL DEFAULT now(), uploaded_by uuid NOT NULL
);

CREATE TABLE place.attendance_mismatch (
  id             uuid PRIMARY KEY,
  upload_id      uuid NOT NULL REFERENCES place.attendance_upload(id),
  attendance_id  uuid,                              -- the app record, if one exists
  candidate_id   uuid, shift_date date NOT NULL,
  uploaded_values jsonb NOT NULL,
  app_values     jsonb,
  mismatch_type  text NOT NULL,   -- 'missing_in_app'|'missing_in_upload'|'time_difference'|'status_difference'
  status         mismatch_status_enum NOT NULL,     -- 'open'|'resolved'
  resolution     text, resolved_value jsonb,
  resolved_by uuid, resolved_at timestamptz
);
```

### 5.4 Geo-fence

```sql
CREATE TABLE place.geo_fence (
  id             uuid PRIMARY KEY,
  location_id    uuid NOT NULL UNIQUE,
  centre_lat     numeric(9,6) NOT NULL,
  centre_lng     numeric(9,6) NOT NULL,
  radius_metres  integer NOT NULL,
  enforcement_mode geofence_mode_enum NOT NULL DEFAULT 'off',  -- 'off'|'warn'|'block'
  is_active      boolean NOT NULL DEFAULT true,
  updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);

CREATE TABLE place.geo_fence_breach (
  id             uuid PRIMARY KEY,
  attendance_id  uuid NOT NULL,
  candidate_id   uuid NOT NULL,
  location_id    uuid NOT NULL,
  recorded_geo   jsonb NOT NULL,
  distance_metres numeric(10,2) NOT NULL,
  action_taken   text NOT NULL,                     -- 'warned'|'blocked'|'flagged'
  occurred_at    timestamptz NOT NULL DEFAULT now()
);
```

**`enforcement_mode` defaults to `off`, which reproduces M8 behaviour exactly** — location recorded,
nothing blocked. *"The location field already exists from M8, so switching this on needs no data
change"* (`M12-I5`).

## 6. State machines

Every one of these runs through `02-11`:

**SalaryRevision:** `pending → approved | rejected → applied` (applied on the effective date, not on
approval — `02-11 §6`)
**SalaryAdvance:** `pending → approved → disbursed → recovering → recovered` \| `written_off`
**SalaryHold:** `pending → approved → held → released` (**release needs its own approval**)
**AttendanceMismatch:** `open → resolved` — *"resolved by a person, not silently overwritten"*

## 9. Frontend — `/workforce`

The requests queue itself is `02-11 §9`.

### 9.1 Salary revision (`M12-I2`)

One associate or a batch, from an effective date. **A bulk revision produces one request per person,
each individually auditable** — the approver can approve 40 and reject 10 with reasons.

*"An effective date in the past is either blocked or requires higher approval"* — implemented as a
threshold rule in `02-11`, so backdating routes to a more senior approver rather than being silently
allowed.

### 9.2 Advances and holds (`M12-I3`)

An advance **records how it will be recovered, not just that it was paid** — method, instalments,
start cycle, and progress. A hold stops the next pay run for that person and **is visible before the
run**, in `03-19`'s pre-lock screen. Release restores normal pay from the next cycle and needs its own
approval.

### 9.3 Attendance upload (`M12-I4`)

Upload, parse, match against app check-ins, list what does not match. Mismatches are **resolved by a
person with a reason, never silently overwritten** — *"resolution is audited because it changes what
gets invoiced and paid."*

Row-level errors are named and valid rows still load (`02-05`'s `<PartialResult/>`).

### 9.4 Geo-fence settings (`M12-I5`)

Per location: centre, radius, and mode — **off / warn / block**. A map preview.

The screen states the migration path plainly: with enforcement **off**, behaviour is exactly as in M8
— location recorded, nothing blocked. Turning it on affects only future check-ins.

A breach report shows attempts outside the boundary.

| **Where does attendance upload come from?** | M8 replaced Excel import with app check-in, yet D23 reintroduces upload | **`AS-54`** — a **reconciliation input, not a capture route.** Client-provided attendance sheets checked against what the app recorded. ## 12. Notes for the implementer

**Build `02-11` first, as a platform component.** The plan says *"the approval engine here is reused
by M15, so build it first of the two"*, and this module is its first consumer. Do not build the engine
inside this module and extract it later.

**Roll geo-fencing out in `warn` mode.** GPS accuracy inside a multi-storey hospital is poor, and a
`block` mode deployed everywhere on day one will stop nurses checking in for shifts they are actually
working — which stops attendance, which stops invoices. Warn, collect breach data for a few weeks,
then decide per site.

**Advance recovery is where the arithmetic bites.** An advance recovered over three instalments,
against a person on hold for one cycle, in a month where their salary was revised, is a real case.
`getPayrollAdjustments` must return a coherent answer for it, and `03-19` must be able to reconcile
what it sent to the engine.
