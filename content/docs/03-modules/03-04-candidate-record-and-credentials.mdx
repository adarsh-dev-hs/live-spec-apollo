**Package** `@apollo/candidates` · **Schema** `candidates` · **Plan** D4, D16, A2, A9 · **Effort** ~82.5pd · **Risk** High `EXT` · **Build in** Phase 2–3 · **Release** Parts 1, 2, 3

## 1. Purpose

Everything Apollo holds about a healthcare professional: who they are, which of the two supply bases
they belong to, the extra fields that differ by candidate category, their credentials with issuer,
validity period and verification method, and the verification team's work queue. One candidate record
spans both supply bases against **one shared credential object**, not a duplicated record with a status
flag.

This module also owns the **single definition of the per-category attribute set** that the requisition
side consumes, so the two cannot drift apart (`AS-04`).

## 2. Scope

### In scope

- Candidate list and record, with availability confidence and last-confirmed timestamp visible
- Supply base membership: permanent pool, shift pool, or both — modelled explicitly
- Credentials: issuer, validity period, verification method, shared across both bases
- The verification queue with **pendency tracked by cause**, and the verification detail view
- Document review against OCR output, with corrections retained for accuracy measurement
- Certification records and the learner-match queue
- The category attribute set: definition, versioning, and the service that serves it to the app, Ops,
  `03-02`/`03-03` and `03-07`
- Duplicate detection and merge — **the single merge implementation** in the platform
- Verification check orchestration through `02-13`, and credential expiry tracking

### Explicitly out of scope

- The candidate mobile app — `03-05`. The app writes to this module's records.
- Candidate authentication — `02-01`.
- The adapter layer and the registries themselves — `02-13`, `04-09`.
- Document OCR — `04-10`. This module reviews its output.
- Consent and retention — `02-12`. This module **asks** before dispatching a check.
- Availability decay and cadence — `03-06`. It writes the confidence value onto this module's record.

### Explicitly not built

- Bulk candidate loads from campuses or partners, walk-in registration, referral tagging. Removed from
  the contract; Apollo handles these by hand.
- Face recognition, biometrics, assessment cheating detection. Later release.
- Producing the **clinical and communication rating**. The field exists on the record and nothing fills
  it in (`OI-A-07`).
- Statutory joining forms — `03-15`.
- Deleting a candidate. Ever. A losing duplicate is merged, never removed.

## 4. Dependencies

**Must exist first:** `02-13` — **without the adapter layer no candidate can be verified**; `02-12`
(consent before any check); `02-04` (documents); `02-03` (categories as reference data); `02-07`;
`02-09` (expiry reminders); `03-13` supplies the migrated pool.

**Consumed by:** `03-05` (the app reads and writes this record), `03-06` (writes availability
confidence), `03-07` (**ranks on credentials, category fields and availability — cannot rank if any of
the three is missing**), `03-08` (quotes the candidate), `03-09`, `03-15`.

**External:** `04-09` registries and aggregator, `04-10` document OCR, and the LMS which does not exist
(`OI-HS-15`).

## 5. Data model

```sql
CREATE TABLE candidates.candidate (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    reference text NOT NULL UNIQUE,
    candidate_category text NOT NULL REFERENCES settings.list_entry(code),
    full_name text NOT NULL,
    phone_e164 text NOT NULL,
    email citext,
    date_of_birth date,
    location jsonb,                          -- city, state, coordinates for travel radius
    profile_state text NOT NULL DEFAULT 'registered' CHECK (profile_state IN
      ('registered','profile_complete','verification_pending','verified','partly_verified','failed')),
    -- written ONLY by 03-06 (M5-I10); read by 03-07. Ownership boundary is deliberate.
    availability_confidence numeric(4,3),
    availability_last_confirmed_at timestamptz,
    availability_payload jsonb,              -- Base A: notice period. Base B: windows + radius.
    -- present and unpopulated: no producing system exists (OI-A-07)
    clinical_communication_rating numeric(3,1),
    is_retained_pool boolean NOT NULL DEFAULT false,   -- red verification does NOT delete
    source text NOT NULL,                    -- 'app' | 'migration' | 'ops' | 'learner_record'
    migrated_from_ref text,                  -- lineage to CPAL (03-13)
    consent_basis text NOT NULL DEFAULT 'app',  -- 'migrated_unverified' blocks cadence (02-12)
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);
CREATE INDEX ON candidates.candidate (candidate_category, profile_state);
CREATE INDEX ON candidates.candidate (availability_confidence DESC NULLS LAST,
                                      availability_last_confirmed_at DESC);
CREATE INDEX ON candidates.candidate USING gin (full_name gin_trgm_ops);

CREATE TABLE candidates.supply_base_membership (   -- A2: a separate base, not a status flag
    candidate_id uuid NOT NULL REFERENCES candidates.candidate(id),
    base text NOT NULL CHECK (base IN ('base_a','base_b')),
    joined_at timestamptz NOT NULL DEFAULT now(),
    left_at timestamptz,
    PRIMARY KEY (candidate_id, base)
);

CREATE TABLE candidates.category_attribute_set (   -- THE definition; M3 consumes it (AS-04)
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_category text NOT NULL REFERENCES settings.list_entry(code),
    version integer NOT NULL,
    fields jsonb NOT NULL,                   -- [{key:'specialty', label, type, options[], required}]
    applies_to text[] NOT NULL DEFAULT '{candidate,requisition}',
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    UNIQUE (candidate_category, version)
);

CREATE TABLE candidates.candidate_attributes (
    candidate_id uuid PRIMARY KEY REFERENCES candidates.candidate(id),
    attribute_set_version integer NOT NULL,
    values jsonb NOT NULL,                   -- nurse: specialty, acuity
                                             -- doctor: specialty, case_mix, grade
                                             -- allied: discipline, equipment, technique
    flagged_values jsonb NOT NULL DEFAULT '{}'::jsonb   -- outside the taxonomy → flagged for review
);

CREATE TABLE candidates.credential (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL REFERENCES candidates.candidate(id),  -- ONE record across both bases
    credential_type text NOT NULL,           -- 'council_registration' | 'qualification' | 'licence'
    issuer text NOT NULL,                    -- council or institution
    registration_number text,
    issued_on date, valid_from date, valid_to date,
    verification_method text NOT NULL CHECK (verification_method IN ('api','manual','document_only')),
    state text NOT NULL DEFAULT 'claimed' CHECK (state IN
      ('claimed','submitted','checking','verified','flagged','rejected','expired')),
    outcome text CHECK (outcome IN ('green','amber','red')),
    document_id uuid,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);
CREATE INDEX ON candidates.credential (candidate_id, state);
CREATE INDEX ON candidates.credential (valid_to) WHERE state = 'verified';   -- expiry sweep

CREATE TABLE candidates.verification_case (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL REFERENCES candidates.candidate(id),
    check_type text NOT NULL,                -- 'identity_aadhaar' | 'pan' | 'council_registration' …
    credential_id uuid REFERENCES candidates.credential(id),
    state text NOT NULL DEFAULT 'queued' CHECK (state IN
      ('queued','in_progress','awaiting_registry','awaiting_candidate','manual_review','resolved')),
    outcome text CHECK (outcome IN ('green','amber','red')),
    pendency_cause text CHECK (pendency_cause IN ('candidate','registry','reviewer')),
    pendency_since timestamptz,
    adapter_call_id uuid,
    overridden boolean NOT NULL DEFAULT false,
    override_reason text, overridden_by uuid,
    opened_at timestamptz NOT NULL DEFAULT now(), resolved_at timestamptz
);
CREATE INDEX ON candidates.verification_case (state, pendency_cause, pendency_since);

CREATE TABLE candidates.candidate_document (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL REFERENCES candidates.candidate(id),
    document_id uuid NOT NULL,               -- files.document
    document_type text NOT NULL,
    extracted jsonb,                         -- OCR output, per-field confidence
    corrected jsonb,                         -- verifier corrections; machine value retained
    review_state text NOT NULL DEFAULT 'pending'
      CHECK (review_state IN ('pending','accepted','rejected')),
    rejection_reason text,
    reviewed_by uuid, reviewed_at timestamptz
);

CREATE TABLE candidates.certification (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL REFERENCES candidates.candidate(id),
    name text NOT NULL, provider text,
    completed_on date,
    source text NOT NULL DEFAULT 'manual' CHECK (source IN ('manual','external')),
    external_ref text,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE candidates.learner_match (      -- unmatched learner records, never discarded
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    inbound_record_id uuid NOT NULL,
    learner_payload jsonb NOT NULL,
    state text NOT NULL DEFAULT 'unmatched'
      CHECK (state IN ('unmatched','matched','candidate_created')),
    matched_candidate_id uuid REFERENCES candidates.candidate(id),
    decided_by uuid, decided_at timestamptz
);

CREATE TABLE candidates.duplicate_candidate (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_a uuid NOT NULL REFERENCES candidates.candidate(id),
    candidate_b uuid NOT NULL REFERENCES candidates.candidate(id),
    match_keys jsonb NOT NULL, score numeric(4,3),
    state text NOT NULL DEFAULT 'suspected'
      CHECK (state IN ('suspected','merged','distinct')),
    surviving_id uuid, decided_by uuid, decided_at timestamptz
);

CREATE TABLE candidates.merge_lineage (      -- neither record is deleted (M1-I12, M4-I21)
    surviving_id uuid NOT NULL REFERENCES candidates.candidate(id),
    merged_id uuid NOT NULL REFERENCES candidates.candidate(id),
    merged_at timestamptz NOT NULL DEFAULT now(),
    merged_by uuid NOT NULL,
    PRIMARY KEY (surviving_id, merged_id)
);
```

## 6. State machines

### `Candidate`

`registered → profile_complete → verification_pending → verified | partly_verified | failed`

A `failed` candidate moves to the **retained pool**; the record is not deleted (`M4-I12`).

### `Credential` (`M4-I13`, `M4-I25`)

| From | Event | To | Rule |
|---|---|---|---|
| — | candidate claims it | `claimed` | |
| `claimed` | document uploaded | `submitted` | |
| `submitted` | dispatched through `02-13` | `checking` | Consent asserted first |
| `checking` | green | `verified` | |
| `checking` | amber | `flagged` | Needs a human |
| `checking` | red | `rejected` | Candidate → retained pool, not deleted |
| `verified` | `valid_to` passes | `expired` | **Distinct from missing** in ranking (`M6-I7`) |
| `expired` | renewal | `submitted` | **Reuses the existing record**, never creates a second |

### `VerificationCase` (`M4-I11`)

`queued → in_progress → resolved`, with three parked states carrying a **pendency cause**:
`awaiting_registry`, `awaiting_candidate`, `manual_review`. Pendency is attributable to a cause, never
shown as one backlog number — a registry outage must surface as a spike in awaiting-registry.

## 8. Events and jobs

**Events emitted:** `candidates.candidate.created` · `.merged` · `.base_changed` ·
`candidates.credential.verified` · `.flagged` · `.rejected` · `.expiring` · `.expired` ·
`candidates.verification.resolved` · `candidates.attribute_set.versioned`.

**Events subscribed:** `files.document.available` → queue OCR; `inbound.record.classified`
(`learner_record`) → learner match; `adapters.call.responded` → resolve the case;
`engagement.availability.confirmed` → nothing (the write is direct, through `03-06`'s service).

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `candidates.run-checks` | on submission | Resolves the check set **by category from configuration**, asserts consent, dispatches through `02-13` |
| `candidates.credential-expiry` | daily | Flags expiring credentials, prompts re-upload, marks expired ones so ranking can see them |
| `candidates.detect-duplicates` | on creation and on merge | Phone-first match; **detects duplicates between the migrated base and app registrations** |
| `candidates.pendency-escalate` | daily | Escalates a stalled case to the responsible party — candidate, verifier or administrator |
