## 1. Purpose

The paperwork side of someone joining as a shift worker. Today it is collected and stored outside the
platform. This module brings it in: an associate profile with the employment details that only matter
once someone is actually working, the statutory forms including PF/UAN transfer and gratuity
nomination, a checklist of documents to collect, and a guided step-by-step flow in the app so the
candidate can do it themselves.

**Payroll cannot run for an associate whose paperwork is incomplete**, which is the operational reason
this exists.

## 2. Scope

### In scope

- Associate profile: employment details, bank details, statutory identifiers, completeness
- Statutory forms, each with its own completion state, returnable with a reason
- Document checklist, differing by role and by state
- The guided in-app onboarding flow
- The onboarding gate that blocks a pay run for an incomplete associate

### Explicitly out of scope

- The candidate record — `03-04`. The associate profile **builds on it rather than duplicating it**.
- Document storage and virus scanning — `02-04`.
- Chasing messages — `02-09`.
- The pay run itself — `03-17`.

### Explicitly not built

- **Filing the statutory returns.** Filing is outside this contract entirely; the forms are collected
  and stored.
- Onboarding for permanent placements. Those candidates join the client directly, not Apollo.
- Offer or contract generation for associates — `03-08` covers offers.

## 5. Data model

```sql
CREATE TABLE onboarding.associate_profile (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL UNIQUE,        -- builds on the candidate record, never duplicates it
    placement_id uuid,
    employment_type text NOT NULL,
    date_of_joining date,
    -- encrypted at column level, access audited (01-10)
    bank_account_enc bytea, bank_ifsc_enc bytea, bank_name text,
    pan_enc bytea, uan_enc bytea, aadhaar_ref_enc bytea, esic_number_enc bytea,
    emergency_contact jsonb,
    state text NOT NULL DEFAULT 'not_started' CHECK (state IN
      ('not_started','in_progress','complete','verified')),
    missing_mandatory text[] NOT NULL DEFAULT '{}',
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);

CREATE TABLE onboarding.statutory_form (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    associate_profile_id uuid NOT NULL REFERENCES onboarding.associate_profile(id),
    form_code text NOT NULL,                  -- 'pf_form_11' | 'uan_transfer' | 'gratuity_nomination' …
    state text NOT NULL DEFAULT 'pending' CHECK (state IN
      ('pending','submitted','returned','verified')),   -- its OWN state, not one overall flag
    payload jsonb,
    document_id uuid,
    returned_reason text,
    submitted_at timestamptz, verified_at timestamptz, verified_by uuid,
    UNIQUE (associate_profile_id, form_code)
);

CREATE TABLE onboarding.checklist_item (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    associate_profile_id uuid NOT NULL REFERENCES onboarding.associate_profile(id),
    document_type text NOT NULL,
    is_mandatory boolean NOT NULL DEFAULT true,
    blocks_payroll boolean NOT NULL DEFAULT true,   -- blocks payroll, NOT the placement
    state text NOT NULL DEFAULT 'awaiting'
      CHECK (state IN ('awaiting','received','accepted','rejected')),
    document_id uuid, rejection_reason text,
    last_chased_at timestamptz
);

CREATE TABLE onboarding.checklist_template (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    role_code text, state_code text,          -- differs by role and by state
    document_types jsonb NOT NULL,
    is_active boolean NOT NULL DEFAULT true
);
```

## 6. State machines

### `AssociateProfile`

`not_started → in_progress → complete → verified`. **Cannot be marked complete with mandatory statutory
fields missing.**

### `StatutoryForm`

| From | Event | To | Rule |
|---|---|---|---|
| — | required for this associate | `pending` | **Each form has its own state, not one overall flag** |
| `pending` | associate submits | `submitted` | Stored as a document and retained |
| `submitted` | Ops returns it | `returned` | **Tells the candidate exactly what to fix**; reappears in the app flow with the reason |
| `submitted` | Ops verifies | `verified` | |

### `ChecklistItem`

`awaiting → received → accepted | rejected`. **A missing document blocks payroll but not the placement
itself.**

## 8. Events and jobs

**Events emitted:** `onboarding.profile.completed` · `onboarding.form.submitted` · `.returned` ·
`.verified` · `onboarding.checklist.item_received` · `onboarding.associate.blocked`.

**Events subscribed:** `placement.placement.joined` where `service_line = 'contractual'` → create the
associate profile and the checklist from the template.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `onboarding.chase-documents` | daily | Chases missing checklist items through `02-09` |
| `onboarding.evaluate-gate` | before each pay run, and daily | Recomputes who is blocked |
