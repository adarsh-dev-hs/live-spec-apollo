**Package** `@apollo/migration` · **Schema** `migration` · **Plan** A10 · **Effort** ~31.0pd · **Risk** High `DATA` · **Build in** Phase 1–2

## 1. Purpose

Move Apollo's existing candidate data out of CPAL and the current tooling into the platform, after which
**the platform becomes the system of record and the old tool is switched off**.

This is the single largest unpriced item in the six months. Nobody has seen the data: how many records,
how complete, how many duplicates, whether fields map cleanly onto the new model. The figures against
these items are **placeholders that hold the shape of the plan, not estimates** — a joint profiling
exercise settles them, and it has not happened.

## 2. Scope

### In scope

- Data profiling: volume, completeness, duplicate rate, and a mapping feasibility assessment
- The migration pipeline: extract, map, load, resumable, re-runnable without creating duplicates
- Delta runs picking up source changes between the main load and cutover
- Duplicate resolution within the migrated base and **between the migrated base and app registrations**
- The operational screens: batch status, failed records, correction and rejection
- Reconciliation against the source total, which is what permits cutover

### Explicitly out of scope

- Cutover itself, legacy retirement and hypercare — `05-05` (`M1-I9`). This module proves the data;
  that step turns the old tool off.
- The candidate merge implementation — `03-04` owns it (`OI-A-03`). This module **calls** it, so there
  is one merge and uniform lineage.
- Environments and the pipeline — `02-15`.

### Explicitly not built

- Migration of anything other than candidate data and its documents. Clients, contracts and rate cards
  are entered fresh in `03-01`; nothing in the plan scopes migrating them.
- A two-way sync with CPAL. One direction, then the old tool is retired.
- Automatic resolution of ambiguous records. A failed record is corrected or rejected **by a person,
  with a reason, and is never lost**.

## 5. Data model

```sql
CREATE TABLE migration.batch (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    source text NOT NULL,                     -- 'cpal' | 'spreadsheet_export' | …
    kind text NOT NULL CHECK (kind IN ('profile','main','delta')),
    state text NOT NULL DEFAULT 'staged' CHECK (state IN
      ('staged','profiled','transformed','loading','paused','loaded','reconciled','cut_over','failed')),
    source_total integer,                     -- what the source said
    extracted_count integer NOT NULL DEFAULT 0,
    mapped_count integer NOT NULL DEFAULT 0,
    loaded_count integer NOT NULL DEFAULT 0,
    exception_count integer NOT NULL DEFAULT 0,
    rejected_count integer NOT NULL DEFAULT 0,
    checkpoint jsonb,                         -- resume point (M1-I11)
    started_at timestamptz, finished_at timestamptz,
    started_by uuid NOT NULL
);
-- a batch cannot be started twice concurrently (M1-I2) — enforced by advisory lock + this index
CREATE UNIQUE INDEX ON migration.batch (source, kind)
  WHERE state IN ('transformed','loading');

CREATE TABLE migration.record (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    batch_id uuid NOT NULL REFERENCES migration.batch(id),
    source_ref text NOT NULL,                 -- the CPAL identifier — lineage, retained forever
    source_payload jsonb NOT NULL,            -- exactly as extracted
    mapped_payload jsonb,
    state text NOT NULL DEFAULT 'extracted' CHECK (state IN
      ('extracted','mapped','loaded','exception','resolved','rejected')),
    candidate_id uuid,                        -- what it became
    exception_reason text, exception_field text,
    rejection_reason text, rejected_by uuid,
    resolved_by uuid, resolved_at timestamptz,
    UNIQUE (batch_id, source_ref)             -- a re-run cannot duplicate a record
);
CREATE INDEX ON migration.record (batch_id, state);

CREATE TABLE migration.profile_result (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    batch_id uuid NOT NULL REFERENCES migration.batch(id),
    total_records integer NOT NULL,
    field_completeness jsonb NOT NULL,        -- per field: % populated
    duplicate_rate numeric(5,4),
    unmappable_fields jsonb NOT NULL,         -- fields with no target (M1-I10)
    sample jsonb,
    produced_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE migration.reconciliation (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    batch_id uuid NOT NULL REFERENCES migration.batch(id),
    source_total integer NOT NULL,
    loaded integer NOT NULL, exceptions integer NOT NULL, rejected integer NOT NULL,
    reconciles boolean GENERATED ALWAYS AS
      (source_total = loaded + exceptions + rejected) STORED,
    checked_at timestamptz NOT NULL DEFAULT now(), checked_by uuid NOT NULL
);
```

Every loaded candidate carries `migrated_from_ref` back to `source_ref` (`03-04`), so lineage survives
the migration.

## 6. State machines

### `MigrationBatch` (`M1-I2`, `M1-I11`)

| From | Event | To | Rule |
|---|---|---|---|
| — | source data staged | `staged` | |
| `staged` | profiling run | `profiled` | **Nothing else in A10 can be sized until this completes** |
| `profiled` | mapping applied | `transformed` | |
| `transformed` | load starts | `loading` | **Cannot be started twice concurrently** |
| `loading` | paused | `paused` | |
| `paused` | resumed | `loading` | **Resumes without reprocessing already-loaded records** |
| `loading` | complete | `loaded` | Counts must reconcile to the source total |
| `loaded` | reconciliation passes | `reconciled` | |
| `reconciled` | cutover (`05-05`) | `cut_over` | **Only now does the platform become system of record** |

### `MigrationRecord`

`extracted → mapped → loaded`, or `extracted → exception → resolved → loaded`, or `rejected` with a
reason **so it is counted and not lost**.

| Job | Trigger | Purpose |
