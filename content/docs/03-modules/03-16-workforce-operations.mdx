## 1. Purpose

The day-to-day changes that happen once people are working: salary revisions for one person or in bulk,
salary advances, and putting a salary on hold or releasing it. Each needs two people — one to request
and one to approve — so nobody can change their own pay. It also covers uploading attendance from
outside and pairing it against what the app recorded, and it is where **geo-fencing enforcement finally
switches on**.

The request-and-approve engine built here is reused by `03-19` for internal timesheet approval, so it
is built first of the two.

## 2. Scope

### In scope

- The maker-checker request engine: request types as configuration, thresholds by value, raiser ≠ approver
- Salary revision, individual and bulk
- Salary advances with a recovery plan, and holds with release
- Attendance upload from outside, paired against app check-ins with mismatch resolution
- Geo-fence configuration and enforcement, for both a site and a per-visit address

### Explicitly out of scope

- Paying anyone — `03-17`.
- Statutory filings.
- Shift attendance capture and timesheets — `03-10`, which this module extends rather than replaces.
- The associate profile — `03-15`.

### Explicitly not built

- Approval chains longer than one checker. Thresholds vary the **seniority** of the approver, not the
  number of steps.
- Retrospective salary revision without a higher approval. An effective date in the past is blocked or
  escalated.
- Any change taking effect before approval.

## 5. Data model

```sql
CREATE TABLE workforce.request_type (
    code text PRIMARY KEY,                    -- 'salary_revision' | 'advance' | 'hold' | 'release'
                                              -- | 'timesheet_internal_approval' (03-19)
    name text NOT NULL,
    approval_thresholds jsonb NOT NULL,       -- [{maxValue, requiredRole}] — seniority by value
    is_enabled boolean NOT NULL DEFAULT true,
    owner_component text NOT NULL             -- a new type is CONFIGURATION, not a build
);

CREATE TABLE workforce.request (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    request_type text NOT NULL REFERENCES workforce.request_type(code),
    subject_type text NOT NULL, subject_id uuid NOT NULL,   -- associate, timesheet …
    batch_id uuid,                            -- bulk: one request PER PERSON, individually auditable
    before_value jsonb, after_value jsonb,    -- what the approver sees
    value_amount numeric(14,2),               -- drives the threshold
    state text NOT NULL DEFAULT 'drafted' CHECK (state IN
      ('drafted','submitted','approved','rejected','applied','cancelled')),
    raised_by uuid NOT NULL, raised_at timestamptz NOT NULL DEFAULT now(),
    approver_role_required text,
    approved_by uuid, approved_at timestamptz,
    rejected_reason text,
    applied_at timestamptz,
    CONSTRAINT raiser_is_not_approver CHECK (approved_by IS NULL OR approved_by <> raised_by)
);
CREATE INDEX ON workforce.request (state, request_type, raised_at);

CREATE TABLE workforce.salary_revision (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    request_id uuid NOT NULL UNIQUE REFERENCES workforce.request(id),
    associate_profile_id uuid NOT NULL,
    current_amount numeric(14,2) NOT NULL, revised_amount numeric(14,2) NOT NULL,
    effective_from date NOT NULL,
    is_retrospective boolean GENERATED ALWAYS AS (effective_from < CURRENT_DATE) STORED
);

CREATE TABLE workforce.salary_advance (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    request_id uuid NOT NULL UNIQUE REFERENCES workforce.request(id),
    associate_profile_id uuid NOT NULL,
    amount numeric(14,2) NOT NULL,
    recovery_plan jsonb NOT NULL,             -- HOW it will be recovered, not just that it was paid
    recovered_amount numeric(14,2) NOT NULL DEFAULT 0,
    state text NOT NULL DEFAULT 'approved'
      CHECK (state IN ('approved','disbursed','recovering','recovered','written_off'))
);

CREATE TABLE workforce.salary_hold (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    request_id uuid NOT NULL UNIQUE REFERENCES workforce.request(id),
    associate_profile_id uuid NOT NULL,
    reason text NOT NULL,
    state text NOT NULL DEFAULT 'requested'
      CHECK (state IN ('requested','approved','held','released')),
    held_from date, released_from date, release_request_id uuid
);

CREATE TABLE workforce.attendance_upload (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid, period_start date NOT NULL, period_end date NOT NULL,
    document_id uuid NOT NULL,
    rows_total integer NOT NULL, rows_loaded integer NOT NULL, rows_failed integer NOT NULL,
    state text NOT NULL DEFAULT 'uploaded'
      CHECK (state IN ('uploaded','matched','resolved')),
    uploaded_by uuid NOT NULL, uploaded_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE workforce.attendance_mismatch (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    attendance_upload_id uuid NOT NULL REFERENCES workforce.attendance_upload(id),
    shift_attendance_id uuid,
    uploaded_row jsonb NOT NULL,
    kind text NOT NULL,                       -- 'time_differs' | 'no_app_record' | 'no_upload_record'
    state text NOT NULL DEFAULT 'open' CHECK (state IN ('open','resolved')),
    resolution text, resolution_reason text,  -- resolved BY A PERSON, never silently overwritten
    resolved_by uuid, resolved_at timestamptz
);

CREATE TABLE workforce.geo_fence (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    scope text NOT NULL CHECK (scope IN ('location','visit_address')),
    location_id uuid,                         -- facility work: the site record
    client_id uuid,
    radius_m integer NOT NULL,
    tolerance_m integer NOT NULL,             -- a phone indoors is less accurate than one outside
    mode text NOT NULL DEFAULT 'off'
      CHECK (mode IN ('off','warn','flag','block')),
    is_enabled boolean NOT NULL DEFAULT false,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);

CREATE TABLE workforce.geo_breach (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    shift_attendance_id uuid NOT NULL,
    geo_fence_id uuid NOT NULL REFERENCES workforce.geo_fence(id),
    distance_m numeric(10,1) NOT NULL,
    action_taken text NOT NULL,               -- 'warned' | 'flagged' | 'blocked'
    occurred_at timestamptz NOT NULL DEFAULT now()
);
```

## 6. State machines

### `Request` (`M12-I1`, `M12-I6`)

| From | Event | To | Rule |
|---|---|---|---|
| — | raised | `drafted` | |
| `drafted` | submitted | `submitted` | Threshold selects the required approver role |
| `submitted` | approved | `approved` → `applied` | **The raiser can never be the approver — enforced in the service, not the screen** |
| `submitted` | rejected | `rejected` | Reason required |
| `drafted`/`submitted` | cancelled | `cancelled` | |

A bulk revision produces **one request per person**, each individually auditable, sharing a `batch_id`.

### `SalaryHold`

`requested → approved → held → released`. A hold **stops the next pay run for that person and is
visible before the run**; release restores normal pay from the next cycle.

### Geo-fence enforcement (`M12-I5`)

| Mode | Behaviour |
|---|---|
| `off` | **Exactly as `03-10` today** — location recorded, nothing blocked |
| `warn` | Candidate sees a warning at check-in; the check-in proceeds |
| `flag` | Check-in proceeds and raises an exception for a person to resolve |
| `block` | Check-in is rejected |

The same check runs for both cases; **only the reference point differs** — the site record for facility
work, the visit address on the shift line for home visits. The location field already exists from
`03-10`, so switching this on **needs no data change**.

## 8. Events and jobs

**Events emitted:** `workforce.request.submitted` · `.approved` · `.rejected` · `.applied` ·
`workforce.hold.applied` · `.released` · `workforce.geo.breached`.

**Events subscribed:** `timesheets.attendance.checked_in` → evaluate the geo-fence when enforcement is
on.

**Jobs**

| Job | Schedule | Purpose |
|---|---|---|
| `workforce.apply-approved` | on approval | Applies the change from its effective date |
| `workforce.pair-attendance` | on upload | Matches uploaded rows against app check-ins and surfaces differences |
| `workforce.recover-advance` | per pay cycle | Applies the recovery plan into `03-17` inputs |
