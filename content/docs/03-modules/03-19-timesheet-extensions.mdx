**Package** `@apollo/timesheets` (extension) · **Schema** `timesheets` · **Plan** D22 (full) · **Effort** ~19.5pd · **Risk** Low `XMOD` · **Build in** Phase 7 · **Release** Part 3

## 1. Purpose

The three things `03-10` deliberately left out of the thin slice: **leave categorisation, overtime
treatment, and an internal Apollo approval route** before a timesheet reaches the client. The same
timesheet then feeds both the client invoice and the payroll input, with no second calculation.

## 2. Scope

### In scope

- Leave types and leave records
- Overtime rules, varying by client and by state
- Internal timesheet approval routing, **reusing the `03-16` approval engine**
- The full timesheet calculation applying leave and overtime **on top of** the M8 attendance data

### Explicitly out of scope

- Shift attendance, the thin-slice timesheet, client approval and the deemed window — `03-10`.
- The approval engine itself — `03-16` (`M12-I6`), built first of the two deliberately.
- Payroll — `03-17`, which consumes the fuller timesheet.

### Explicitly not built

- Leave entitlement, accrual or balance tracking. Leave is **categorised**, not administered.
- Absence management or return-to-work workflows.
- A second calculation path. One timesheet feeds both invoicing and payroll.

## 5. Data model

```sql
CREATE TABLE timesheets.leave_type (
    code text PRIMARY KEY,                    -- configurable, NOT hardcoded
    name text NOT NULL,
    is_paid boolean NOT NULL,
    counts_towards_hours boolean NOT NULL,
    is_active boolean NOT NULL DEFAULT true
);

CREATE TABLE timesheets.leave_record (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    candidate_id uuid NOT NULL,
    leave_type_code text NOT NULL REFERENCES timesheets.leave_type(code),
    from_date date NOT NULL, to_date date NOT NULL,
    shift_demand_line_id uuid,                -- when it displaces a specific shift
    recorded_by uuid NOT NULL, recorded_at timestamptz NOT NULL DEFAULT now(),
    note text
);
CREATE INDEX ON timesheets.leave_record (candidate_id, from_date, to_date);

CREATE TABLE timesheets.overtime_rule (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid,                           -- rules differ by client…
    state_code text,                          -- …and by state
    threshold_hours numeric(6,2) NOT NULL,
    threshold_basis text NOT NULL CHECK (threshold_basis IN ('per_shift','per_week','per_period')),
    multiplier numeric(4,2) NOT NULL,
    effective_from date NOT NULL,
    is_active boolean NOT NULL DEFAULT true
);

CREATE TABLE timesheets.approval_route (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid, location_id uuid,
    required_role text NOT NULL,
    min_value numeric(14,2),
    is_enabled boolean NOT NULL DEFAULT true
);

-- 03-10's timesheet gains two columns rather than a parallel table
ALTER TABLE timesheets.timesheet
  ADD COLUMN internal_approval_request_id uuid,     -- workforce.request (03-16)
  ADD COLUMN internally_approved_at timestamptz;

ALTER TABLE timesheets.timesheet_line
  ADD COLUMN leave_record_id uuid REFERENCES timesheets.leave_record(id),
  ADD COLUMN overtime_hours numeric(6,2) NOT NULL DEFAULT 0,
  ADD COLUMN overtime_rule_id uuid REFERENCES timesheets.overtime_rule(id),
  ADD COLUMN overtime_value numeric(14,2) NOT NULL DEFAULT 0;
```

Extending the existing tables rather than shadowing them is what makes AC "one timesheet feeds both the
client invoice and the payroll input, with no second calculation" achievable.

## 6. State machines

### `Timesheet`, extended (`M15-I2`)

```
 building ──▶ built ──▶ internally_approved ──▶ sent_for_approval ──▶ approved | deemed_approved ──▶ invoiced
                  │                                     ▲
                  └──▶ returned with a reason ───────────┘  (does not reach the client until corrected)
```

The state was **declared in `03-10`'s enum and unused** until now, so adding this step is not a
migration of live data.

**The client-side waiting period only starts once the client link is actually sent** — internal
approval does not consume any of it.

## 8. Events and jobs

**Events emitted:** `timesheets.timesheet.internally_approved` · `.internally_returned` ·
`timesheets.leave.recorded` · `timesheets.overtime.applied`.

**Events subscribed:** `timesheets.timesheet.built` → raise an internal approval request through
`03-16`; `workforce.request.approved` (type `timesheet_internal_approval`) → move to
`internally_approved`.

**Jobs**

| Job | Trigger | Purpose |
|---|---|---|
| `timesheets.apply-leave-overtime` | on build | Applies leave and overtime **on top of** attendance, without replacing it |
| `timesheets.recalculate` | on correction | Produces a consistent result on recalculation |
