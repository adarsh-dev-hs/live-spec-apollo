## 1. Purpose

The client side of the business: the hospital or home-healthcare provider, its sites and departments,
the rates agreed with it, and the signed contract. Two things here matter more than they look. First,
the list of email addresses and WhatsApp numbers belonging to each client — `02-08` checks every
incoming message against it to work out who sent a requisition. Second, the contract terms, because the
billing engine reads them **at the moment it decides to raise an invoice**, and there is no fallback:
without contract terms, permanent billing does not run at all.

## 2. Scope

### In scope

- Client entity with legal name, GST, billing address, service lines and **care setting**
- Locations and departments, with home-healthcare sites having no departments
- Client contacts, including who receives which type of tokenised link
- Sender identities: email addresses, WhatsApp numbers and HRMS tenants mapped to exactly one client
- Rate cards by role, skill and location, versioned by effective date, with a **baseline rate** and the
  permanent placement fee percentage
- Contracts with versioning, renewal alerts and history
- The three per-client waiting periods, each with a platform default fallback
- The two resolution services billing depends on: rate lookup and contract-terms lookup

### Explicitly out of scope

- Client login and self-service — `03-14`, Phase 6.
- Link issuing and the link pages — `02-14`. This module holds the contacts; that one holds the links.
- Invoicing and receivables — `03-11`.
- The shared list component — `02-07`, first needed here.

### Explicitly not built

- Writing contracts from a template. Contracts are **recorded here, not drafted**.
- Credit limits and credit control. Billing stops at invoice raised.
- Client-side user provisioning in Release 1 (`OI-A-04`).
- E-signature of the client contract. The signed document is attached; signing happens outside.

## 5. Data model

```sql
CREATE TABLE clients.client (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    legal_name text NOT NULL,
    trading_name text,
    gst_number text,                         -- required before an invoice can be raised
    billing_address jsonb,
    care_setting text NOT NULL REFERENCES settings.list_entry(code),  -- hospital | home_healthcare
    service_lines text[] NOT NULL,           -- {'permanent'} | {'contractual'} | both
    status text NOT NULL DEFAULT 'draft'
      CHECK (status IN ('draft','active','suspended','closed')),
    owner_user_id uuid REFERENCES identity.user(id),   -- alerts and escalations route here
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);

CREATE TABLE clients.location (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL REFERENCES clients.client(id),
    name text NOT NULL,
    address jsonb NOT NULL,
    geo_point point,                         -- geo-fence reference for facility work (03-16)
    care_setting text NOT NULL REFERENCES settings.list_entry(code),
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE clients.department (            -- absent for home healthcare
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    location_id uuid NOT NULL REFERENCES clients.location(id),
    name text NOT NULL,
    is_active boolean NOT NULL DEFAULT true
);

CREATE TABLE clients.client_contact (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL REFERENCES clients.client(id),
    location_id uuid REFERENCES clients.location(id),
    full_name text NOT NULL, role_title text,
    email citext, phone_e164 text, whatsapp_e164 text,
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE clients.sender_identity (       -- 02-08 resolves every inbound against this
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL REFERENCES clients.client(id),
    location_id uuid REFERENCES clients.location(id),   -- binds so requisitions default correctly
    identity_type text NOT NULL CHECK (identity_type IN ('email','whatsapp','hrms_tenant')),
    identity_value citext NOT NULL,
    is_active boolean NOT NULL DEFAULT true,
    linked_from_inbound_id uuid,             -- when created by resolving an unmatched record
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);
-- an identity maps to EXACTLY ONE client; a second claim is blocked at entry (M2-I6, M3 V1)
CREATE UNIQUE INDEX ON clients.sender_identity (identity_type, identity_value) WHERE is_active;

CREATE TABLE clients.rate_card (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL REFERENCES clients.client(id),
    name text NOT NULL
);

CREATE TABLE clients.rate_card_version (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    rate_card_id uuid NOT NULL REFERENCES clients.rate_card(id),
    version integer NOT NULL,
    effective_from date NOT NULL,
    status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','in_effect','superseded')),
    permanent_fee_pct numeric(5,2),          -- 5–6% of CTC, per contract, never a constant
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    UNIQUE (rate_card_id, version)
);

CREATE TABLE clients.rate_card_line (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    rate_card_version_id uuid NOT NULL REFERENCES clients.rate_card_version(id),
    role_code text NOT NULL,
    skill_code text,
    location_id uuid REFERENCES clients.location(id),
    candidate_category text REFERENCES settings.list_entry(code),
    agreed_rate numeric(14,2) NOT NULL,
    baseline_rate numeric(14,2),             -- what A11 reports variance against (M9-I11)
    rate_unit text NOT NULL CHECK (rate_unit IN ('per_shift','per_hour','per_placement_pct')),
    currency text NOT NULL DEFAULT 'INR'
);
CREATE INDEX ON clients.rate_card_line (rate_card_version_id, role_code, skill_code, location_id);

CREATE TABLE clients.contract (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    client_id uuid NOT NULL REFERENCES clients.client(id),
    reference text NOT NULL UNIQUE,
    status text NOT NULL DEFAULT 'draft'
      CHECK (status IN ('draft','active','renewed','expired','terminated')),
    current_version integer NOT NULL DEFAULT 1,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE clients.contract_version (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    contract_id uuid NOT NULL REFERENCES clients.contract(id),
    version integer NOT NULL,
    service_lines text[] NOT NULL,
    starts_on date NOT NULL, ends_on date NOT NULL,
    value numeric(14,2), currency text NOT NULL DEFAULT 'INR',
    permanent_fee_pct numeric(5,2),          -- per contract (M9-I12)
    rate_card_version_id uuid REFERENCES clients.rate_card_version(id),
    guarantee_period_days integer,           -- OI-A-13 — if > 90, credit/debit notes return to R1
    payment_terms_days integer,              -- used by 03-20 ageing
    signed_document_id uuid,                 -- files.document
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    UNIQUE (contract_id, version)
);

CREATE TABLE clients.client_window_config (
    client_id uuid PRIMARY KEY REFERENCES clients.client(id),
    retention_confirmation_days integer,     -- null → platform default (02-03)
    timesheet_approval_days integer,
    requisition_followup_days integer,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL
);
```

## 6. State machines

### `Client` (`M2-I2`)

| From | Event | To | Rule |
|---|---|---|---|
| — | created | `draft` | Cannot be created without the fields the invoice requires (GST, billing address) |
| `draft` | activated | `active` | Service lines constrain which requisition types can be raised |
| `active` | suspended | `suspended` | **Does not orphan open requisitions; blocks new ones** |
| `suspended`/`active` | closed | `closed` | Same rule |

### `Contract` (`M2-I8`, `M2-I9`)

| From | Event | To | Rule |
|---|---|---|---|
| — | created | `draft` | |
| `draft` | activated | `active` | **Cannot activate without the terms the billing triggers require** |
| `active` | renewed | `renewed` → new `active` version | Prior version remains retrievable |
| `active` | end date passes | `expired` | Blocks new requisitions for that client, **not open ones** |
| any | terminated | `terminated` | Reason required; full history retained |

### `RateCardVersion`

`draft → in_effect → superseded`. Old versions are **never deleted** — an old requisition must still
price against the rate that applied when it was raised.

| `GET`/`POST`/`PATCH` | `/v1/contracts` | `contract:read` / `contract:manage` | List with renewal window; create; edit |
| `POST` | `/v1/contracts/:id/activate` · `/renew` · `/terminate` | `contract:manage` | Lifecycle |

Both resolution endpoints are also in-process calls. `03-11` uses `contract-terms/resolve` at the
moment a trigger fires, never at invoice generation time.
