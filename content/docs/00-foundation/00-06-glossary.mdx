## Plan identifiers

| Form | Meaning | Example |
|---|---|---|
| `M<n>-I<k>` | Engineering index — one per buildable item in the delivery plan. The reference used in tickets and tests. | `M3-I12` = Fulfilment board |
| `M<n>` | Milestone. M0 foundations, M1–M9 Release 1, M10–M15 Release 2. | `M3` = Demand Intake & Allocation |
| `D<n>` | Apollo's own deliverable number, carried unchanged | `D2` = Demand management |
| `A<n>` | Apollo deliverable added at the revision | `A13` = Client link surfaces |
| `F<nn>` | Platform prerequisite Hiresense identified; not in Apollo's list | `F03` = Role & permission model |
| `OI-…` | Open decision. Prefix says the source: `OI-A-` (Part A), `OI-M3-` (Part B M3 chapter), `OI-HS-` (Hiresense-raised) | `OI-A-13` = guarantee period |
| `AS-<nn>` | Working assumption held until an open item closes | `AS-01` |
| `P<nn>` / `B<nn>` | **This documentation's** component IDs — platform and business | `P10` = client link tokens |

## Business terms

| Term | Meaning |
|---|---|
| **Base A / Base B** | The two supply bases. Base A = permanent placement candidates. Base B = the shift pool, employed by Apollo, contacted every 3–4 days. |
| **Acuity** | How intensive the nursing care is (ICU vs general ward). A nurse attribute and a requisition attribute. |
| **Allied health** | Physiotherapists, radiographers, lab technicians, pharmacists — the third candidate category alongside nurses and doctors. |
| **Case-mix** | A doctor attribute: the profile of conditions they routinely handle. |
| **Challan** | An Indian statutory payment/remittance form (PF, ESIC). We produce them; someone else files them. |
| **Contractual** | Apollo's word for the shift-staffing business (Flow B). Apollo employs the worker. Contrast with *permanent*. |
| **CPAL** | Apollo's existing legacy candidate tool. Source of the A10 migration; retired once the platform reconciles. |
| **Deemed approval / deemed confirmation** | When a client never replies, the platform treats the answer as given after a configurable waiting period, so revenue does not stall. |
| **Demand** | A client's requirement. Becomes a `Requisition`. |
| **Dunning** | Chasing overdue invoices on a schedule. M15. |
| **Fulfilment board** | The operational heart of demand management: live demand, ageing and fill in one view. Highest-traffic screen in the platform. |
| **Guarantee period** | How long Apollo guarantees a replacement if a permanent placement leaves. **Open (`OI-A-13`)** — if it runs past day 90, credit notes move into Release 1. |
| **Maker-checker** | Two-person control: the person who raises a change can never be the person who approves it. |
| **MIS pack** | Monthly management information pack for Apollo leadership. Generated on a schedule, not assembled by hand. |
| **Pendency** | How long a verification case has been waiting. Tracked and reported. |
| **Permanent** | The placement-fee business (Flow A). The client employs the person; Apollo bills 5–6% of salary at day 90. |
| **Preceptor** | The senior clinician mentoring a new joiner. Asked about in trial check-ins — its absence predicts drop-out. |
| **Requisition** | The normalised demand record. One schema regardless of which of five channels it arrived on. |
| **Retained pool** | Candidates kept on file indefinitely. Conflicts with DPDP erasure rights (`OI-HS-02`). |
| **Shift demand line** | One row per shift, expanded from a shift template. Contract staffing only. |
| **Site-resident recruiter** | One of 15 recruiters based at a hospital. They capture requirements verbally — this is a primary path, not an edge case. (7 more are "floating".) |
| **TDS** | Tax Deducted at Source. Indian clients withhold tax when paying an invoice, so gross and net must both be visible. M15. |
| **Trial period** | The 90 days after joining. Check-ins at day 0, 7, 30, 60, 90. Day 90 is the billing trigger. |
| **UAN** | Universal Account Number — the portable PF identifier. Transferred during associate onboarding. |
| **Verbal capture** | A recruiter typing in a requirement given to them in person or by phone. A first-class intake path. |

## Regulatory & external

| Term | Meaning |
|---|---|
| **DPDP** | Digital Personal Data Protection Act, India. Drives residency (ap-south-1 only), consent before verification, retention policy and erasure. |
| **DigiLocker** | Indian government document wallet. Route to Aadhaar verification. |

| **INC / NUID** | Indian Nursing Council / Nurses Unique ID — nursing registration. |
| **NMC** | National Medical Commission, plus state medical councils — doctor registration. |
| **PF** | Provident Fund. Statutory deduction and reporting. |
| **BSP** | Business Solution Provider — the intermediary for WhatsApp Business API. Approves message templates, which takes weeks. |
| **D-U-N-S** | Business identifier Apple requires for organisation developer enrolment. |

## Technical terms as used here

| Term | Meaning in this codebase |
|---|---|
| **Component** | One implementable unit with one spec file, one package, its own tables. 34 of them. |
| **Module** | Backend package under `packages/modules/`. Owns its tables; exposes a router, service interface, events, jobs, permissions. |
| **Platform component** | A module used by two or more business modules. Built first. |
| **Port / Adapter** | Port = our interface for an external system. Adapter = the implementation against a specific supplier. Every port has a fake for tests and a manual fallback for reality. |
| **Outbox** | Table written inside the business transaction; a relay publishes from it. Guarantees an event is never lost or emitted for a rolled-back change. |
| **Projection** | A reporting table derived from `event_store` by replaying events. Rebuildable from scratch. |
| **Temporal lookup** | Resolving a value *as at a date* rather than now. Rate cards and contract terms. Getting this wrong is a billing error. |
| **Scope resolver** | The layer that limits a query to the rows the current user may see (their sites, their client). Row-level, not screen-level. |
| **Deemed window** | A configurable waiting period after which a non-response is treated as an answer. |
| **Thin slice** | A deliverable partly in Release 1, remainder in Release 2 (D14, D22, D25). Both halves have specs; the R1 half must not be built in a way that blocks the R2 half. |
| **Link type** | One of four configured instances of the single tokenised client-link mechanism. Only day-90 and timesheet approval may trigger billing. |

## Naming conventions quick reference

| Thing | Convention | Example |
|---|---|---|
| Package | `@apollo/<kebab>` | `@apollo/requisitions` |
| Postgres schema | lower snake | `demand` |
| Table | lower snake, **singular** | `requisition_version` |
| Column | lower snake | `deemed_approved_at` |
| Enum type | `<table>_<column>_enum` | `requisition_status_enum` |
| API route | `/api/v1/<kebab-plural>` | `/api/v1/requisitions` |
| Event | `<module>.<entity>.<past-tense>` | `demand.requisition.closed` |
| Queue | `<module>.<verb>` | `intake.parse` |
| Permission | `<module>.<resource>.<action>` | `demand.requisition.close` |
| Setting key | `<module>.<name>` | `demand.follow_up_window_days` |
| Feature flag | `ff.<module>.<name>` | `ff.attendance.geofence_enforcement` |
| React component | PascalCase | `FulfilmentBoard.tsx` |
| Hook | `use<Thing>` | `useRequisition.ts` |
| Test | `<subject>.test.ts` | `requisition.service.test.ts` |
