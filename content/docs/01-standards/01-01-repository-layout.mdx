## 2. Inside a module package

Every `modules/*` package has the same five folders. No exceptions, no cleverness.

```
modules/requisitions/
├── src/
│   ├── index.ts          # the ONLY public surface: exported services + types. Nothing else is importable.
│   ├── routes/           # Fastify plugins. Thin: validate → call service → shape response.
│   ├── services/         # business logic. Owns transactions. Emits events. Writes audit.
│   ├── repositories/     # hand-written SQL. One file per aggregate. No business logic.
│   ├── domain/           # entities, state machines, invariants. Pure. No I/O.
│   ├── jobs/             # queue handlers and schedules registered with 02-10
│   └── events/           # this module's emitted event schemas
├── test/
│   ├── unit/             # domain, pure
│   ├── integration/      # service + real Postgres (testcontainers)
│   └── contract/         # what other modules rely on
└── project.json          # Nx target config
```

## 3. Boundary rules (enforced, not advisory)

`nx.json` tag rules, failing the build on violation:

| Rule | Effect |
|---|---|
| A `modules/*` package may import `packages/*` and other modules **only through `src/index.ts`** | No reaching into another module's repositories or tables |
| A `modules/*` package may **never** import `apps/*` | Modules stay deployable-agnostic |
| An `apps/*` package may import any module and any package | Composition happens at the app |
| An `integrations/*` package may import `packages/*` only | An integration never knows about business modules; the module calls it |
| `apps/edge` may import `packages/*` and `@apollo/inbound` only | A Lambda verifies, persists the raw payload and enqueues. Business logic there would run outside the transaction, audit and event guarantees of `01-02` |
| `packages/contracts` imports nothing but `zod` | It is the shared truth; a cycle through it poisons everything |
| A platform module (`02-*`) may **never** import a business module (`03-*`) | Dependencies point one way |

Two `modules/*` packages that need each other's data do it through the owner's exported service —
which is also where the audit write and the event emit live, so a direct table read would silently
skip both.

## 4. Naming

| Thing | Convention | Example |
|---|---|---|
| Package | `@apollo/<kebab>` | `@apollo/demand-intake` |
| Folder | kebab-case | `modules/demand-intake/` |
| File | kebab-case | `requisition-state-machine.ts` |
| Type / class | PascalCase | `RequisitionVersion` |
| Function / variable | camelCase | `resolveRateForDate` |
| Constant | SCREAMING_SNAKE | `MAX_OTP_ATTEMPTS` |
| DB schema, table, column | snake_case, table singular | `demand.requisition.days_aged` |
| Event | `<schema>.<entity>.<past-tense>` | `demand.requisition.status_changed` |
| Queue | `<module>.<action>` | `engagement.cadence-run` |
| Route | plural kebab | `POST /v1/requisitions/:id/hold` |
| Migration | `NNNN_<verb>_<subject>.sql` | `0043_add_requisition_care_setting.sql` |

## 5. Commands

| Command | Does |
|---|---|
| `npm run dev` | api + worker + console with hot reload against a local Postgres and Redis |
| `npx nx run-many -t build` | build everything, cached |
| `npx nx affected -t test lint typecheck` | only what the diff touches — the default in CI |
| `npm run db:migrate` / `db:reset` | apply migrations / drop, recreate, migrate, seed |
| `npm run seed:demo` | one client, one contract, one requisition, one candidate — the G1 fixture |
| `npx nx graph` | render the dependency graph; use it before adding an import |
| `docker compose up -d` | Postgres, Redis, LocalStack (S3/SES/EventBridge) and MailHog for local work |
| `npm run build:images` | build the `api`, `worker` and `edge-*` images exactly as CI does |

## 6. Rules that are cheap now and expensive later

1. **A module never queries another module's schema.** The Postgres role per schema makes it fail, not
   just lint (`01-05`).
2. **Nothing imports from a deep path.** `import { x } from '@apollo/requisitions'`, never
   `'@apollo/requisitions/src/services/foo'`.
3. **`packages/contracts` is the only place a request or response shape is defined.** If the console
   and the API disagree, one of them did not import it.
4. **No module has its own `pg` pool.** `@apollo/db` exports one.
5. **No `any` at a module boundary.** Inside a function, sometimes. Across `index.ts`, never.
