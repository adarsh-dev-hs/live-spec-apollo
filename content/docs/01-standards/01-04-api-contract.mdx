**Package** `@apollo/contracts` · **Schema** `n/a` · **Plan** D11, D12, A1, A13 · **Effort** — · **Risk** Low · **Build in** Phase 1

REST/JSON over HTTPS, schema-first. `@apollo/contracts` is the single definition of every request and
response; the API validates against it, the OpenAPI document is generated from it, and the four
clients import it.

## 1. Shape

| Rule | Detail |
|---|---|
| Base | `/v1` — the version is in the path and changes only on a breaking change |
| Resources | plural kebab nouns: `/v1/requisitions`, `/v1/shift-demand-lines` |
| Sub-resources | `/v1/requisitions/:id/versions`, `/v1/candidates/:id/credentials` |
| State transitions | a POST to a named action, not a PATCH of a status field: `POST /v1/requisitions/:id/hold` |
| Verbs | `GET` read · `POST` create or act · `PATCH` partial update · `DELETE` only for genuinely removable things (a saved view, a rate line draft). **Never** for candidates, requisitions, invoices or any audited record |
| Content | `application/json; charset=utf-8`; file upload via presigned S3 URL from `02-04`, never multipart through the API |
| Time | RFC 3339 UTC with `Z`. Business dates are `YYYY-MM-DD` and mean `Asia/Kolkata`. |
| Money | `{ "amount": "12500.00", "currency": "INR" }` — string, never a float |

## 2. Envelopes

Single resource:

```json
{ "data": { "id": "0192f3…", "reference": "REQ-2026-000431", "status": "in_fulfilment" } }
```

Collection — cursor pagination everywhere, because offset pagination over the migrated base is
unpredictable (`OI-A-02`):

```json
{
  "data": [ { "id": "…" } ],
  "page": { "cursor": "eyJpZCI6…", "hasMore": true, "limit": 50 },
  "meta": { "totalApprox": 1284 }
}
```

`totalApprox` is an estimate and is labelled as such on screen. An exact count is only computed when a
list is exported (`02-07`), where the plan requires the export to return **exactly the filtered rows**.

## 3. Errors — RFC 9457 Problem Details

```json
{
  "type": "https://docs.apollo.internal/errors/precondition-failed",
  "title": "Close reason is required",
  "status": 422,
  "detail": "A requisition cannot be closed without a reason from the configured list.",
  "code": "REQUISITION_CLOSE_REASON_REQUIRED",
  "correlationId": "01JD8F…",
  "errors": [ { "field": "reasonId", "code": "required", "message": "Select a close reason." } ]
}
```

`code` is stable and machine-readable; `title`/`detail` are human and may change. Clients switch on
`code`, never on `detail`.

## 4. Listing conventions (used by `02-07`)

| Parameter | Form | Note |
|---|---|---|
| `filter[field]` | `filter[status]=open,in_fulfilment` | Repeated values are OR; different fields are AND |
| `sort` | `sort=-daysAged,clientName` | `-` is descending |
| `cursor`, `limit` | `limit` max 200, default 50 | |
| `q` | free-text search where the resource supports it | |
| `view` | a saved view id, expanding to a filter set | `M2-I14` |

**Every list endpoint applies the principal's data scope before any filter.** Scope is not a
parameter and cannot be widened by the caller (`01-07`, `OI-HS-01`).

## 5. Idempotency and concurrency

| Mechanism | Where |
|---|---|
| `Idempotency-Key` header, required on POSTs that create money, messages or external calls | invoices, offers, link issues, message sends, payroll submissions |
| Webhook idempotency by provider message id | `02-08`, `02-09` — redelivery is normal and must not create a second `InboundRecord` (`M3-I18`) |
| `If-Match` / `ETag` on records two people edit at once | requisition, contract, candidate, rate card |
| A duplicate link submission returns the **original** response, not a second answer | `M7-I18` |

## 6. Auth

| Realm | Credential | Header |
|---|---|---|
| `staff` | Session cookie, `HttpOnly` `Secure` `SameSite=Lax`, sliding idle expiry from settings | cookie |
| `candidate` | Bearer access token (short) + rotating refresh token | `Authorization: Bearer` |
| `client_user` | Session cookie, separate cookie name and separate signing key from staff | cookie |
| `link` | Opaque token in the path, exchanged for a single-record, single-action session | path |
| provider webhook | Signature verification per provider; unsigned providers are IP-allowlisted and shared-secret'd | provider-specific |

Realms never mix. A candidate token presented to a staff route is a 401, not a 403 (`AS-06`).

## 7. Versioning

- Additive changes (new optional field, new endpoint, new enum value a client may ignore) go into `v1`.
- Breaking changes create `v2` for that resource; `v1` is kept for one release with a deprecation
  header. In practice this should not happen inside six months — but the **integration contracts**
  (`02-13` adapters, `04-13` finance export, `04-14` payroll) are versioned independently because
  their counterparties are not on Apollo's release train.
- The reference implementation of "a new market implements three interfaces without a core change"
  (`M1-I13`) is a contract test that fails if a core change breaks an existing adapter.

## 8. Generated artefacts

| Artefact | From | Consumed by |
|---|---|---|
| `openapi.json` | Fastify route schemas at build time | docs, the client generator, `M1-I6` technical documentation |
| `@apollo/contracts` types | Zod schemas | console, links, portal, mobile |
| Typed API client | `openapi.json` + `operationId` | all four clients |

The technical documentation deliverable (`M1-I6`, D11) is generated from this, not written by hand,
and is versioned alongside the release.

## 9. Public link endpoints (`02-14`) are different on purpose

| Rule | Why |
|---|---|
| No `/v1` browsing surface — a link session can call exactly the endpoints its type allows | Enumeration of another client's shortlist is the worst failure mode here |
| Rate-limited per token and per IP | Tokens arrive over WhatsApp and can be forwarded |
| No collection endpoints at all | A link reaches one record |
| Responses omit every field the client does not need — internal reason codes, scores, notes | `M4-I6`, `M10-I4`: client-appropriate status, never internal reasoning |
