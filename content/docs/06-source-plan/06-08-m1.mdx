### Built once, used elsewhere

Two things here are built once and used everywhere. The console shell (navigation, page frame, permissions) is used by every Ops screen in the platform. The registry adapter interface is used by M4 for every identity and credential check. It also carries two pieces of foundation work that nothing before it needs: the design system and the deployment pipeline and environments.

### Records this milestone owns

- User, Role, Permission — who can log in and what they can do. Every other module reads these.
- MarketAdapter, AdapterCall — the configuration for each outside registry, and a log of every call made to one.
- MigrationBatch, MigrationRecord, MigrationException — the old-data import: what came in, what loaded, what failed.
- SystemConfig — platform-wide default settings. M2 falls back to these when a client has none set.

### How records move

- MigrationBatch: staged → profiled → transformed → loaded → reconciled → cut over
- MigrationRecord: extracted → mapped → loaded. Or extracted → exception → resolved → loaded. Or rejected, with a reason.
- AdapterCall: requested → responded, giving green, amber or red. Or failed → retried. Or falls back to a person checking it by hand.

### Not in this milestone

- Adapters for the US, Germany and Ireland. India only for now. The interface must be able to take them later without changing the core app.
- The LMS. Apollo's own team is building it. It will connect by API later. Nothing here depends on it.
- Any client login. The client portal (D12) is a later milestone, so logins here are for Apollo staff only.
- Statutory filing (PF, ESIC returns). Not in this contract at all.

### Needs to exist first

- Nothing. This milestone goes first.

### What breaks without it

- Everything. No environment and no login means nothing else can be built or tested. No adapter layer means M4 cannot verify anyone. No migration means the candidate pool is nearly empty when matching starts.

#### M1-I2 — Migration screens

`A10` · `Screen` · `L · 3.0pd` · `AI Medium` · `High` · `DATA` · `Low`

**Who uses it: Platform administrator, Hiresense.** Start, pause and watch the data import from the old system. Shows counts and progress.

##### Screens to build

1. **Migration status**
  - Lists each migration run with how many records were read, loaded and failed
  - Starts, pauses and resumes a run
2. **Failed records**
  - Lists records that did not load, with the reason
  - Opens one to correct the field that failed and send it back to load

##### Conditions it must satisfy

- A batch reports extracted, mapped, loaded, exception and rejected counts that reconcile to the source total
- A paused batch resumes without reprocessing already-loaded records
- A batch cannot be started twice concurrently
- Progress is observable while a batch runs, not only on completion
- Effort and volume cannot be estimated until profiling runs (OI-A-02)
