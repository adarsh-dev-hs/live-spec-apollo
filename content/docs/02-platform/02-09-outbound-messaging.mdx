**Package** `@apollo/messaging` · **Schema** `messaging` · **Plan** F07, D10 · **Effort** ~42.0pd · **Risk** High `EXT` · **Build in** Phase 3

## 1. Purpose

Everything the platform sends and the plumbing under it: templates per channel and purpose, triggers
binding an event to a message, one sending path across WhatsApp, SMS, email and app push, retry,
delivery receipts, opt-out and preference handling, and a log per message and per candidate. D10 covers
templates and preferences; the queue, retries and delivery receipts underneath are assumed by the
client's list and named as F07.

First needed when A1 chases a client for missing requisition fields on the channel the requisition
arrived on — which is why it lands in Phase 3 with the inbound pipeline rather than in Phase 4 with the
cadence engine that later drives most of its volume.

## 2. Scope

### In scope

- Message templates per channel and purpose, with variables resolved from candidate, requisition,
  placement or invoice records (`M5-I1`)
- **WhatsApp provider approval state** on a template; an unapproved template cannot be sent
- Triggers: which event sends which message, on which channel, to whom, with a fallback order
  (`M5-I2`)
- The sender: one path across WhatsApp, SMS, email and app push, each provider behind an interface
  (`M5-I8`, `M3-I30`)
- Retry, suppression and asynchronous receipt reconciliation (`M5-I9`)
- Delivery log with cost attribution, and per-candidate contact history (`M5-I3`, `M5-I4`)
- Contact preferences and opt-out, honoured **at selection**, not at send
- One registered WhatsApp number and template set shared with A1 follow-up — one registration, not two

### Explicitly out of scope

- **Who to contact and how often.** The cadence engine, segments and availability decay are `03-06`.
  This component sends what it is told to send.
- Inbound message handling — `02-08`.
- Voice calls — the campaign and provider live in `03-06`/`04-04`. Voice is not a template channel.
- The candidate-facing notification settings screen — `03-05` (`M4-I9`), reading this component's
  preference store.

### Explicitly not built

- Campaign performance reporting beyond the send log. That reporting sits in `03-12`.
- Guided multi-step conversations over WhatsApp. WhatsApp sends messages and fixed-button templates;
  anything guided happens in the app (plan convention).
- Structured inbound handling for SMS and email replies (`OI-A-17`).
- A staff-facing in-app notification centre.

## 5. Data model

```sql
CREATE TABLE messaging.template (
    id          uuid PRIMARY KEY DEFAULT uuidv7(),
    code        text NOT NULL,            -- 'requisition_followup' | 'availability_check' | 'offer_delivery' …
    channel     text NOT NULL CHECK (channel IN ('whatsapp','sms','email','push')),
    purpose     text NOT NULL,            -- 'operational' | 'statutory' | 'contractual' | 'cadence'
    locale      text NOT NULL DEFAULT 'en-IN',
    subject     text,                     -- email only
    body        text NOT NULL,            -- {{candidate.firstName}}, {{requisition.reference}} …
    variables   jsonb NOT NULL,           -- declared variable names, validated at save
    provider_template_name text,          -- WhatsApp only
    approval_state text NOT NULL DEFAULT 'not_required'
      CHECK (approval_state IN ('not_required','draft','submitted','approved','rejected')),
    approval_submitted_at timestamptz, approval_decided_at timestamptz, approval_note text,
    is_active   boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now(), updated_by uuid NOT NULL,
    UNIQUE (code, channel, locale)
);

CREATE TABLE messaging.trigger (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    code        text NOT NULL UNIQUE,
    event_name  text NOT NULL,            -- a 02-11 event name
    audience    text NOT NULL,            -- 'candidate' | 'client_contact' | 'requisition_owner' | 'user'
    channel_order text[] NOT NULL,        -- ['whatsapp','sms','email'] — fallback order
    template_code text NOT NULL,
    purpose     text NOT NULL,
    is_enabled  boolean NOT NULL DEFAULT true,   -- disabling stops sending without deleting history
    created_at timestamptz NOT NULL DEFAULT now(), created_by uuid NOT NULL
);

CREATE TABLE messaging.message (
    id uuid PRIMARY KEY DEFAULT uuidv7(),
    template_id uuid REFERENCES messaging.template(id),
    trigger_id  uuid REFERENCES messaging.trigger(id),
    cadence_rule_id uuid,                 -- engagement.cadence_rule — why this send happened (M5-I4)
    cause       text NOT NULL,            -- 'demand.followup' | 'engagement.cadence' | 'selection.offer'
                                          -- | 'placement.checkin' | 'billing.dunning' | 'auth.otp'
    channel     text NOT NULL,
    purpose     text NOT NULL,
    recipient_type text NOT NULL CHECK (recipient_type IN ('candidate','client_contact','user')),
    recipient_id uuid NOT NULL,
    recipient_address text NOT NULL,      -- phone or email, as sent
    subject_type text, subject_id uuid,   -- the record this is about
    rendered_body text NOT NULL,
    status      text NOT NULL DEFAULT 'queued' CHECK (status IN
                  ('queued','sent','delivered','read','failed','given_up','suppressed')),
    provider    text, provider_message_id text, provider_error text,
    attempts    integer NOT NULL DEFAULT 0,
    queued_at   timestamptz NOT NULL DEFAULT now(),
    sent_at timestamptz, delivered_at timestamptz, failed_at timestamptz,
    cost_units  numeric(12,4),            -- conversations, segments, minutes
    cost_currency text,
    correlation_id text NOT NULL
);
CREATE INDEX ON messaging.message (recipient_type, recipient_id, queued_at DESC);
CREATE INDEX ON messaging.message (status, queued_at);
CREATE INDEX ON messaging.message (cause, queued_at);      -- cost attribution (OI-HS-05)
REVOKE UPDATE (rendered_body, recipient_address) ON messaging.message FROM PUBLIC;

CREATE TABLE messaging.contact_preference (
    recipient_type text NOT NULL, recipient_id uuid NOT NULL,
    channel text NOT NULL,
    is_allowed boolean NOT NULL DEFAULT true,
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (recipient_type, recipient_id, channel)
);

CREATE TABLE messaging.opt_out (
    recipient_type text NOT NULL, recipient_id uuid NOT NULL,
    scope text NOT NULL CHECK (scope IN ('all','cadence','marketing')),   -- statutory always sendable
    reason text, opted_out_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (recipient_type, recipient_id, scope)
);

CREATE TABLE messaging.suppression (      -- permanent failures: invalid number, hard bounce
    address text PRIMARY KEY,
    channel text NOT NULL, reason text NOT NULL,
    suppressed_at timestamptz NOT NULL DEFAULT now()
);
```

## 6. State machines

### `Message` (`M3-I30`, `M5-I9`)

| From | Event | To | Rule |
|---|---|---|---|
| — | enqueued | `queued` | Opt-out, suppression and send window already checked at **selection** |
| `queued` | provider accepted | `sent` | Optimistic |
| `sent` | provider receipt | `delivered` | **Receipt backfill corrects an optimistic `sent`** |
| `delivered` | read receipt (WhatsApp) | `read` | |
| `queued`/`sent` | transient failure | `queued` (attempts+1) | Exponential backoff, capped |
| `queued`/`sent` | permanent failure | `failed` → `given_up` | **No retry**; address suppressed and flagged on the record |
| `queued` | attempts exhausted | `given_up` | Dead-lettered, **visible and re-queueable by an operator** |
| — | recipient opted out of this purpose | `suppressed` | Recorded, not silently dropped |

### `Template` approval (`M5-I1`)

`draft → submitted → approved | rejected`. An **unapproved WhatsApp template cannot be sent** —
enforced in the sender, not just the UI. The lead time is displayed on the template because it gates
cadence go-live (`X01`).

## 7. API surface

| Method | Path | Permission | Purpose |
|---|---|---|---|
| `GET`/`POST`/`PATCH` | `/v1/messaging/templates` | `template:manage` | Template CRUD, variable validation, preview |
| `POST` | `/v1/messaging/templates/:id/submit-approval` | `template:manage` | Submit to the BSP |
| `POST` | `/v1/messaging/templates/:id/test-send` | `template:manage` | **To a nominated internal recipient, never a candidate** |
| `GET`/`POST`/`PATCH` | `/v1/messaging/triggers` | `template:manage` | Trigger CRUD, enable/disable |
| `GET` | `/v1/messaging/messages?channel=&status=&from=&to=` | `message:read` | Delivery log |
| `GET` | `/v1/messaging/messages?recipientType=&recipientId=` | `message:read` | Contact history |
| `POST` | `/v1/messaging/messages/:id/requeue` | `message:manage` | Re-queue a given-up message |
| `GET`/`PUT` | `/v1/messaging/preferences` | candidate, or `message:manage` | Channel preferences |
| `POST` | `/v1/messaging/opt-out` | candidate | Opt out of a scope |
| `POST` | `/hooks/messaging/:provider/receipt` | `edge-webhook` | Delivery receipt reconciliation |

In-process: `messaging.send({ templateCode, recipient, variables, cause, purpose, subject })`. Every
caller in the platform uses this; nobody calls a provider directly.

## 8. Events and jobs

**Events emitted:** `messaging.message.queued` · `.sent` · `.delivered` · `.failed` · `.given_up` ·
`messaging.template.approved` · `messaging.opt_out.recorded`.

**Events subscribed:** every event bound to an enabled `Trigger`.

**Jobs**

| Job | Trigger | Purpose |
|---|---|---|
| `messaging.send` | on demand, `interactive` class | Resolves channel by preference then fallback order, renders, calls the provider |
| `messaging.retry-and-receipts` | every minute | Retries transient failures; reconciles late receipts |
| `messaging.reap-given-up` | hourly | Surfaces dead letters to the operator UI |

Rate limits per provider are respected **rather than discovered through throttling** (`M5-I8`), and
every send records its cost units attributed to its `cause` (`OI-HS-05`).
